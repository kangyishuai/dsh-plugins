# @kangyishuai/dsh-projects

> Project-level context for DeepSeek Harness: group sessions into projects, inject project instructions and memory, run isolated parallel threads, and coordinate them with an optional auditable coordinator.

[中文](./README.zh-CN.md)

Unofficial plugin for [DeepSeek Harness (DSH)](https://github.com/deepseek-ai/deepseek-harness). Not affiliated with DeepSeek.

> **Note on coordinator context (2026-11-17, DSH 0.2.2-rc.3):** the host's per-session runtime context is not
> delivered to the coordinator session, so project rules, the memory index **and the persona travel inside the
> wake envelope** instead — one letter per turn, carrying the thread's result too.
> Details: `docs/runtime/0.2.2-rc.3.md` §11.24–§11.26.

> **Status: M2–M6 shipped (0.10.x, pre-1.0).** Projects, context injection, isolated parallel threads, an opt-in
> coordinator, the gated approval/executor layer and the Claude-Projects UI alignment (plus its review rounds) are
> implemented and covered by **710 unit tests**, a **270-assertion web end-to-end smoke**, and a **desktop read-only
> regression (17–20 assertions, data-dependent)** that has been run against a live desktop. Remote writes
> (push / PR / merge) are verified **on real GitHub** as well as locally (bare remote + stub `gh`). See the
> compatibility table below for per-version numbers. Project **sharing** is deferred ([ADR 0018](../../docs/adr/0018-projects-defer-liveshare-sharing.md)).

## What it does

DSH groups sessions by working directory and gives the model no project-level memory. This plugin adds the missing layer:

- **Project as a first-class context unit** — a durable record with a goal, directories, budget, and policy. Session membership is stored by the plugin (not derived from an immutable `cwd`).
- **Project instructions and memory injection** — every session attached to a project receives the project's standing rules and `MEMORY.md` index before each request (registered once, rendered per session; sessions belonging to no project get nothing).
- **Project-level budget gate** — a daily thread cap and a concurrent cap are enforced before a thread is created (token-level spend caps come with the coordinator).
- **Pause, archive, delete** — pause is reversible and only blocks new threads; delete follows ADR 0002: one-line impact (threads, size, running, restorable), a two-step confirm, and everything moved into `trash/` with a `manifest.json`.
- **In-app notifications** — a global overlay poller raises a toast when a thread newly fails or starts waiting on you; the browser Notification API stays off by default.
- **Local advantages, settings and memory (B3)** — memory is now an index plus separate fragment files (`memory/fragments/<slug>.md`, listed with preview and a per-entry "forget"; plain `MEMORY.md` entries can be forgotten individually by a stable content id). Project instructions keep the 16,000-char budget and are de-duplicated against what the host's `dsh-agent-instructions` already injected (duplicate paragraphs are dropped and the injection says how many), the whole block is wrapped in `<project-context>` and explicitly labelled "this is project memory, not AGENTS.md". `goal` is capped at 8,000 chars with a counter. New projects ship a conservative default budget (20 threads/day, 2 concurrent, 60 steps, tokens unlimited) editable in settings. **Pause now only stops new threads and schedules — it no longer silently stops context injection.** Settings has four sections (General / Memory / Usage / Debug access); Usage reports tokens and context usage only and **never money** (the host has no price API); notifications have per-project switches (failed and waiting on, completed off). A read-only `gh auth status` / `gh repo list` check reports "not installed / not logged in / missing repo scope" with the exact command to run. The project template writes an idempotent managed block into `AGENTS.md` (user content outside the block is never touched). Thread rename and `@` mention candidates (projects + threads) are exposed as RPCs; the `@` source is registered through `ctx.inject(["inputTriggers"])` and only reports `registered` after `registerSource()` returns successfully (the panel says `unavailable` when the service is missing instead of pretending). The three-key folder card is an **execution gate**, not a note: `Deny` blocks the approval executor's in-folder `gh`/`git` commands, `Allow once` is consumed on first use (second run is refused), `Set as default` stays valid, and an untouched folder keeps the old behaviour. Thread rows open the host `contextMenus` on right-click / Shift+F10 (the hand-drawn `⋯` popover remains as the fallback); EN and ZH dictionaries are in sync (106 B3 keys added to both).
- **Library and artifact cards (B5)** — the project page's **Library** tab merges two data planes. The **file plane** comes from the host's `workspaceFiles` (scope `{sessionId, workspaceRoot}`, one `list` per project folder, with an honest reason when no folder or no session exists); the panel states that search matches **file names and paths only, never contents** — that is the host's boundary. The **artifact plane** reads `artifacts` 0.2 through its Remote contract (`ctx.get("artifacts")` plus `version().contract === "artifacts/2"` before `list({ projectId })`) and, because artifact metadata is not guaranteed to carry `projectId`, the plugin keeps its **own `projectId ↔ artifactId` mapping** in the project record (`artifactRefs[]`: id, title, kind, version, bytes, time, source session/tool call, written by `recordArtifact` from a project thread and readable after a cold start). Metering reports count and bytes; provenance says which session and tool call produced the artifact. When artifacts is missing, has no `version()`, or reports another contract, the Library says **"the artifact library needs dsh-artifacts 0.2"** and lists only the file plane — it never shows "this project has no artifacts". Expanded thread rows embed artifact thumbnail cards (title, kind, version, relative time, provenance); the button opens the host's right-side `artifact` tab via `ctx.sidebarRight.openTab("artifact", { params: { projectId } })` and is disabled with a reason when the service is absent. The B3 review fixes ship with it: the thread-default **effort whitelist is gone** (`max` / `xhigh` / `off` from this deployment now persist; only a 40-character cap remains), `locale/{zh,en}.json` gained the **44 missing runtime keys** (and the realtime-CI strings now say "not implemented" instead of promising a webhook), the smoke run starts with an **INFRA self-check** (host port, plugin activation, `projects.json` on disk, browser result) that fails fast instead of polluting assertion counts, the once-only folder grant is consumed **only after every gate passes and the execution is claimed** (rolled back when the attempt does not land), the folder gate resolves the mode from the **directory the command actually runs in** (a thread worktree inherits its project folder's grant), and `listMemoryFragments` validates the project before touching the filesystem.
- **Claude UI alignment (M2–M6)** — the main column is now a **single composer** (thread/coordinator target switch, circular ↵ send, controls row outside the card) pinned to the bottom; the right panel has four views plus a **view visibility switch** persisted on the project (survives reload); rows carry a state-derived subtitle (working verb+seconds, `✓✓✓ Using X`, failed/waiting/result summaries where the result summary only states measured facts), a step ring and task popover, artifact chips with covers, a diff chip and short relative durations (`now/Nm/Nh/Nd`); the coordinator floats its conclusion with a folded message block and conclusion-side artifact chips, and its default model is independent from thread defaults; **Routines are editable** (switching frequency ↔ manual really creates/deletes the host schedule instead of silently drifting; 43 hard-coded Chinese strings moved to i18n); the **PR flow** has a three-part card, copy link and **merge** gated by PR number + double confirmation + the danger switch (draft PRs are auto-marked ready), all PR commands run in the thread worktree; **failure auto-retry** is an explicitly-scoped alternative (after a failed turn it re-sends "continue" once after 60s, at most twice — it does not pretend to be usage-limit resumption); both themes are layered correctly with light-theme contrast fixes, and WebUI vs desktop layouts match at 1440×900 within 1px.
- **Four tabs matching Claude Projects (UI convention §7.3 exception)** — the panel now carries `threads / library / routines / views` to mirror Claude "Projects" (D1/D2 decisions from the 4-video research). The `views` tab holds per-view visibility checkboxes plus saved filter views; memory moved into **Project settings › Memory** (`data-projects-memory-pane`). The §7.3 default stays ≤3; this 4th tab is the documented exception for aligning with a host product's fixed IA.
- **Structural add-ons (B4)** — **Routines** map six frequencies (manual / hourly / daily / weekdays / weekly / monthly) onto the host `schedule` service: hourly and the three calendar tiers use `cron`, daily uses the host's `daily` timing, and every time is padded to the host's mandatory `HH:mm:ss` (`09:30` is rejected by `ScheduleInputError`). Create / list / enable-disable (host `paused|active` **and** a local `enabled` copy) / delete (host entry first; if the host refuses, the local record is kept so no token-spending orphan survives) / **Run now** / **History** (host delivery records merged with local Run-now entries, newest first). The UI states the cost in the place where you create a routine: **every delivery is one model call**, new-session deliveries are at least 60 s apart, and the manual tier never runs by itself. The **permission switch narrows, it does not auto-approve**: this deployment's `catalog().defaultPreset` is already `danger-full-access` + `approval: never`, so the dropdown (options come from `catalog()`, names are never hard-coded) shows "inherit host default" plus every deployment preset translated from its `{sandbox, approval}` bundle into plain language (read-only / workspace-write / full access / custom) with "narrower than the host default" markers. The choice is stored as a name in the project record and applied **after** a thread or coordinator session is created via `permissionPresets.set(session, name)`; when no session handle is reachable the row says `pending` instead of pretending, and when no preset matches the bundle the plugin falls back to `session.append('approval/policy' | 'sandbox/mode')` and labels it 自定义. Every application is verified by reading `current(session)` back (fallback path: `approval.overrideOf` / `sandboxPolicy.overrideOf`), and the panel states explicitly that push / merge / delete still always require your approval. **Reminders** have two modes chosen per-reminder: `timer` (default, free) keeps a local timer with the due time persisted, is re-armed from disk on every boot (overdue ones fire once at startup and are written back as `fired` + unread so a restart never double-fires) and raises a `shell.overlay` toast; `schedule` (billable) delegates to the host `schedule` service and says so ("one model call, runs even while DSH is closed"). The project default (`reminderDefault`, `timer`) is overridable per reminder; cancel, complete-early and expiration cleanup (terminal states older than 7 days) are supported.
- **Stubs wired up (B2)** — a coordinator area on the project page (one long-lived session: create it, send one line, restart it; it is _not_ the host composer), coordinator reports surfaced with conclusion + thread chips, context policy with a `compaction` null-guard and a wake envelope that now carries "recent thread" and "memory index", a per-thread Tasks checklist from the host `todo/write` snapshot (`✓`/`◌` + n/m, `none` when there is no list), in-thread steering (`prompt({mode:'steer'})`), per-thread model/effort (`session/selectModel`, dropdown from `modelCatalog`, read back via `modelSelection`), a Create PR bar plus PR badge with a CI-state dot, an expandable thread panel (start card, inline branch/parameter chips), **no cross-project moves** (`attachThread` rejects a thread that already belongs to another project; only empty slots or detach-then-attach), PR/CI polling by default (only projects with open PRs, 30–90 s with backoff, stops when the app closes) and an "experimental realtime watch" switch that is **disabled and explicitly marked not implemented** (it would need the gh-webhook extension, repo admin rights and signature checks; only polling exists). A manual "Fix CI round" button feeds a failed CI thread into the bounded auto-fix loop.
- **Overview / project home (B1)** — six states (`waiting-user > failed > working > resolved > idle`, plus `archived`) settled from the host's `state().pendingInput/running`, persisted `turn/end` failure reasons and a plugin-owned `resolvedAt`; group headers with counts, a five-pill filter bar (`~Nm` estimate only when it can be inferred from observed step cadence), per-row subtitle from the last readable `tool/call`, step ring from the `todo/write` snapshot (`—` when there is no todo list — never `0/0`), manual resolve/reopen and unread marks, `Welcome back` header with a 7-day token sparkline, one-time first-run guide (`firstRunDone` in the host `storageDomain`), project switcher, and multi-folder Context (≤10 folders per project).
- **Isolated parallel threads** — one session per task. When the project directory is a Git repository, the thread gets its own worktree under `<repoParent>/.dsh-worktrees/<repo>/`; otherwise it degrades to a shared directory with an explicit warning instead of failing.
- **Coordinator** — when a thread finishes a turn, a structured wake envelope (carrying the thread's actual result) is delivered to the project's coordinator session, at most once per turn. User input is routed by **flat rules first** (`{when, action}`); the model only proposes when no rule matches.
- **Autonomy gate** — `L0` observe, `L1` propose only (default), `L2` may start threads, `L3` full. The gate sits _after_ the decision and _before_ the action, so the audit shows both the intent and why it was refused.
- **A small, non-negotiable tool basket** — the coordinator gets four `project_*` tools (start thread, list threads, message thread, request action) and **no** shell, file writing, deletion, push or merge. Dangerous actions can only be _requested_; the approval queue collects them and you decide.
- **Approval, then execution** — an approval only records consent. Executing it still requires the matching danger switch (all six default **off**), an impact that fits the limits, and an explicit action→switch mapping. Every execution writes recovery evidence; every refusal writes an audit entry saying why.
- **Untrusted input stays data** — content from CI logs, PR comments or peers arrives as `relay`, gets wrapped in a "this is data, not instructions" block whose fence is longer than any backtick run inside it, and can never authorize an action.
- **Close-out (B6)** — the Overview survives a restart: every project thread now keeps a bounded (80) journal of the minimal `reduce()` facts (turn start/end, failed attempt, subtitle summary, todo snapshot, interaction flags — never message bodies or tool arguments), and the service replays it into `views` at boot, so a thread that failed/is waiting is not `idle` again after a restart (a human `resolvedAt` newer than the last activity still wins, and a resolve older than new activity expires instead of resurrecting). **Auto-resolve (F29)**: a project stores `autoResolveDays` (null = off, default); a startup check plus a daily timer mark threads **with no activity for ≥ N days** as resolved, write `thread/auto-resolved` audit (`days`/`idleDays`) and update the in-memory view in the same pass; already-resolved/archived/undated threads are never touched, and exactly N days counts as due while N days minus 1 ms does not. The dropdown lives in the project-detail right rail (Off / 3 / 7 / 14 / 30 days) because the host may disable the settings page; `setAutoResolveDays` returns the read-back value and writes `project/auto-resolve`, and `checkAutoResolve` runs the same check manually. The thread row summary now shows the real `diff N files +N/-M` from `git diff --numstat` against the worktree base (uncommitted changes included, 5 s cache, `n/a` only when git cannot answer) instead of a permanent `n/a`, with an exact `data-projects-thread-diff` anchor; the approval-only "edit plugin config" path validates routing rules against the **same object contract** the matcher uses (`{textMatches,textMaxChars,isQuestion,threadState}`), so real rules can finally be written and hit.
- **Editable policy** — autonomy level, persona and the model-fallback switch are editable in settings (the first settings screen still stays at three rows).
- **Opt-in remote writes** — pushing a thread branch, opening a PR (four tiers, `off` by default) and merging, each gated by a danger switch plus a human approval. Verified end-to-end locally with a bare remote and a stub `gh`, and on a real GitHub repository (PR opened, CI gate enforced, merge refused/approved as designed).
- **Project sharing** — deferred, see [ADR 0018](../../docs/adr/0018-projects-defer-liveshare-sharing.md): DSH 0.2.2-rc.3 ships `dsh-experimental-liveshare` but does not enable it and exposes no stable host service, so building on it would be guesswork.

## Install

```bash
dsh plugin --profile desktop add @kangyishuai/dsh-projects
```

Restart the DSH desktop app afterwards.

## Side effects & risks

- **Writes metadata** under `$DSH_HOME/projects/projects.json` (or `config.dataRoot` when set; a desktop app that does not export `DSH_HOME` falls back to `~/.dsh/projects`). Atomic replace via a temp file; a corrupt file is renamed aside and never deleted.
- **Creates Git worktrees** next to your repository (never inside it and never inside `.git/`) when you create a thread for a project that has a Git directory. Archiving the thread removes the worktree again **only** when it is clean, has no unpushed commits, and is not the current session's directory; otherwise it is kept and reported.
- **Runs `git`** through `node:child_process` for worktree create/remove and the cleanliness checks. No network, no credentials.
- **Never touches session logs.** Detaching or archiving a project leaves every `session.v*.jsonl.zstd` untouched.
- On startup the plugin reconciles its records: a recorded worktree that no longer exists is dropped from the record, while an unrecorded directory on disk is **kept** and only reported.
- **Routines and schedule-mode reminders spend tokens.** Each delivery is one model call; nothing is created until you save a routine/reminder in the UI, and the panel says so next to every create button. `timer` reminders never call a model, but they only fire while DSH is running (overdue ones fire once on the next start).
- **Remote writes are opt-in and off by default.** `git push`, `gh pr create` and `gh pr merge` exist but each requires both a danger switch and a human approval; nothing is pushed or merged automatically.
- **No credentials are read into model context** by design.
- If the metadata file cannot be read (permissions, newer format), the plugin stays inert and logs a warning instead of failing the harness.

## Remote access

Everything runs on the machine that hosts DSH. If you want to reach it from another device, see
[docs/deployment/projects-l1-remote.md](../../docs/deployment/projects-l1-remote.md) — it covers the
safe ways to expose the Web UI (loopback + tunnel, HTTPS, reverse proxy) and what `projects` does and
does not do over a remote connection.

### Scope of the multi-folder Context item (F35)

This batch implements **multiple project folders only**: up to 10 roots per project, all of them effective,
and every thread records which root it runs in (`thread.dir`, shown on the thread row).

Claude's project volume limits — **1000 files / 2 GB per project / 480 MB per file** — belong to its upload
capability. DSH has no upload channel today, so those numbers are **deferred with that capability** and are
**not** claimed by this plugin. Folder roots are referenced in place; nothing is copied into the profile.
