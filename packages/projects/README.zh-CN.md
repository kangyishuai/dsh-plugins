# @kangyishuai/dsh-projects

> 把项目做成一等上下文单元：会话归属、项目级指令与记忆注入、每线程独立工作树、可审计的协调器，以及可封顶的成本闸。

[English](./README.md)

非官方 [DeepSeek Harness (DSH)](https://github.com/deepseek-ai/deepseek-harness) 插件，与 DeepSeek 无关。

> **状态：早期开发（M1）。** 项目仓储已实现并有测试；上下文注入、线程面板与协调器尚未发布。本版本**不会**写任何远端仓库。

## 做什么

DSH 按工作目录给会话分组，且模型看不到项目级记忆。本插件补上这一层：

- **项目是一等上下文单元** —— 一条持久记录，带目标、目录、预算与策略。会话归属由插件自己存（不依赖不可变的 `cwd` 现算）。
- **项目指令与记忆注入**（M1，进行中）—— 归属某项目的会话在每次请求前收到该项目的常设规则与 `MEMORY.md` 索引。
- **隔离的并行线程**（M2）—— 每个任务一个会话；项目目录是 Git 仓库时，每个线程一份独立 worktree。
- **「需要我」总览**（M2）—— 线程状态从会话事件日志推导，不依赖模型自报。
- **可选协调器**（M3）—— 事件驱动唤醒、规则优先的路由（带可读决策记录）、每项目自治级别。默认 `L1`（只提议、不启动）。
- **可选远端写入**（M4）—— draft PR 与 auto-fix 循环，默认全关，且每个动作都必须挂在人产生的授权上。

## 安装

```bash
dsh plugin --profile desktop add @kangyishuai/dsh-projects
```

装完重启 DSH 桌面版。

## 副作用与风险

- **写元数据**到 `$DSH_HOME/projects/projects.json`（配置了 `config.dataRoot` 时写到那里）。用临时文件原子替换；文件损坏时**改名隔离**，绝不删除。
- **不碰会话日志。** 解绑或归档项目不会改动任何 `session.v*.jsonl.zstd`。
- **本版本没有远端写。** `git push`、`gh`、任何合并动作都还没实现；将来也是 opt-in 且默认关。
- **设计上不把凭据读进模型上下文。**
- 元数据读不出来（权限、版本更新）时，插件保持静默并记一条警告，不会让宿主启动失败。
