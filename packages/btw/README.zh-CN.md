# @kangyishuai/dsh-btw

> **不打断主任务的只读旁问。**

[English](./README.md)

[DeepSeek Harness (DSH)](https://github.com/deepseek-ai/deepseek-harness) 的非官方插件，与 DeepSeek 官方无关。

## 做什么

`/btw <问题>` 就当前工作提一个旁问，**不打断主任务、也不进入对话历史**。

- **回合进行中可用**：命令立即派发，不排到当前回合之后（实测 215 ms，且不产生用户消息）。
- **只读**：旁问在 fork 出来的子代理里执行，**不给任何工具**；guard 挂在子代理自己的作用域上，它发起的工具调用一律被拒，`send_message` 永远拒绝。
- **便宜**：fork 复用主会话的提示前缀，服务端大部分走缓存（实测首次 fork 命中 57%，重复请求 94%），且不产生写缓存费用。
- **可留存**：答案写入按会话切分的 JSONL 历史，裸 `/btw` 可重新打开上一条。
- **可追问**：同一条旁问可以继续追问，线程内的问答每轮都会回放给模型。
- **流式输出**：抽屉里答案边生成边显示，不用等整段返回（host 缓冲子会话的 text-delta，面板通过 `btw/live` 读取）。
- **Markdown 渲染**：标题、列表、表格、引用、代码块与行内样式都会正常渲染；转正草稿保留 Markdown 源码，发送后由 DSH 正常渲染。
- **数字可读**：成本徽章的 token 数自适应 `K/M/B/T`，耗时自适应 `ms/s/m/h`（例如 `新增 12.3K · 命中缓存 988K · 32.5s`）。
- **一键转正**：把**整条线程**整理成四节 **Markdown** 草稿（首问 / 最后一轮结论 / 关键细节（含每轮追问）/ 仍未解决），**只插进输入框、绝不发送**，发不发由你决定。
- **原生右侧栏**：点「旁问」在 DSH 右侧边栏打开一个「旁问」tab，主对话变窄但**不被遮挡**；点右侧栏右上角的收起按钮（⌥⌘B）收起整栏，再点「旁问」展开。宿主没有右侧栏服务时回退到右侧浮层抽屉。
- **聊天式顺序**：线程从旧到新、每轮问答按时间展开，最新一条在最下面，打开或新内容到达时自动滚到底。
- **诚实的范围徽章**：抽屉会说明有多少条旁问，并提示**模型能看到完整会话**；范围档位只缩窄指令，不裁剪上下文。

## 怎么实现的

第三方 DSH 插件**拿不到带 provider adapter 的 `ctx.llm` 实例**（所有取法都返回无 adapter 的实例）。受支持的路径是 **fork 子代理**：

1. `ctx.subagents.startActivation({ provider: 'fork', parent: agent, … })` —— 父 `Agent` 来自命令调用上下文；
2. 只读 guard 挂在**子代理自己的 ctx** 上（`ctx.agents.get(childId).ctx.tools`）：宿主把 guard 注册到「调用方 ctx 的 scope 层」，检查时只看 `[global, ...agent scope 链]`，所以经子代理挂的 guard 只约束这一次旁问（及其自己的子代理）。插件**绝不**用自己的（无 scope 的）ctx 挂 guard —— 那会落到宿主的**全局层**，在旁问运行期间拒绝整个进程里所有 agent 的工具调用。取不到子代理 ctx 时宁可不挂（结果里 `guardScope: "none"`），提示词仍然禁止用工具；
3. 从 activation 结果里取答案，归档子会话避免污染会话列表，并把问答追加进历史。

追问每轮**重新 fork** 并把线程内的问答回放进提示词 —— fork 是单轮语义，让一个子会话活着续聊会退化成
完整的 side session（更重、要管会话生命周期）。

流式文本只留在 host 进程内存里：`llm/stream` 观察器按子会话 id 截取 `text-delta`，最多保留 12k 字符，
面板轮询 `btw/live`，run 结束即释放。**刻意不**让 client 订阅子会话：fork 出来的子会话带着父会话全部已完成轮次
作为种子，client 一旦 retain 就会把整段历史拉到浏览器里，而旁问只需要最后几 KB 的增量。
Markdown 在 host 解析成 JSON 块树，client 只做 React 元素映射 —— 不注入 HTML、不引构建器、不加载宿主 UI 包。

转正只由 host **返回文本**，客户端用 composer 的 `setDraft` 插入，**从不调用 `submit`**；
输入框已有内容时直接拒绝，不覆盖你正在写的东西。草稿四节用 `##` 标题保留 Markdown 源码，
落进输入框是未渲染原文，发送后由 DSH 渲染。

范围是刻意做成**建议性**的：fork 会继承父会话全部已完成轮次，插件无法只继承一部分。
徽章如实说明这点，而不是假装上下文被裁剪过。

## 安装

```bash
dsh plugin --profile desktop add @kangyishuai/dsh-btw
```

装完重启 DSH 桌面版。

## 用法

```
/btw 刚才那个配置文件叫什么来着？
/btw                      # 重新打开上一条答案
/btw --thread <线程id>    # 在已有线程里继续追问
/btw --scope recent <问题> # 提示回答聚焦的范围（session | recent | selection）
```

面板点输入框左侧的「旁问」按钮打开：注册在 **DSH 原生右侧栏**（`sidebar.right.pane.tab`）里，
主对话会变窄但不被面板遮挡。点右侧栏右上角的收起按钮（⌥⌘B）收起整栏（tab 保留），再点「旁问」展开；tab 自带的 × 或
面板里的「关闭」按钮关闭 tab。宿主未加载右侧栏服务时，自动回退到右侧浮层抽屉（可收起成右边缘小条）。

线程从旧到新排列、每轮问答展开，最新一条在最下面；打开抽屉或有新内容时自动滚到底。
答案按 Markdown 渲染，超长时折叠为「展开全文」。底部输入框发起新旁问；
点线程里的「追问」会出现该线程自己的输入框。

## 配置

插件配置（把插件加进 profile 时设置）：

| 键             | 默认                   | 含义                                                           |
| -------------- | ---------------------- | -------------------------------------------------------------- |
| `allowedTools` | `[]`                   | 允许旁问使用的工具名。空 = 完全只读。`send_message` 永不放行。 |
| `language`     | `auto`                 | `en` / `zh`；`auto` 跟随系统语言。                             |
| `dataRoot`     | `$DSH_HOME` → `~/.dsh` | 历史与设置文件的位置（`<dataRoot>/btw/`）。                    |

运行期设置（在**设置 → 旁问**里改，落在 `<dataRoot>/btw/settings.json`）：

| 键               | 默认    | 含义                                                                                                                       |
| ---------------- | ------- | -------------------------------------------------------------------------------------------------------------------------- |
| `allowedTools`   | `[]`    | 非空时覆盖上面的插件配置。                                                                                                 |
| `historyLimit`   | `50`    | 每会话保留的旁问条数（1–200）。服务端每次读/写历史都用这个值：改小后旧记录立刻不再展示，并在下一次旁问落盘时从文件里裁掉。 |
| `echoAnswer`     | `true`  | 主对话是否回显完整答案；关闭后只在旁问面板展示。                                                                           |
| `boundedContext` | `false` | 会话上下文超过 400K tokens 时，改用 spawn 子代理只带最近 12 条消息，不为整段父会话付费。opt-in；可能丢较早上下文。         |

设置文件每次使用前重读，改完不需要重启宿主。

转正**只插入未发送的草稿**，绝不发送。草稿按当前输入框宽度收进 6 行：短线程保留四节 Markdown 原文；长线程变成「首问 + 结论开头」的摘要，末尾指回旁问面板（完整答案留在面板里）。

面板交互细节：追问输入框打开时底部「新旁问」输入会暂时隐藏（避免两个输入框），追问按钮叫「追问」/「取消追问」；
`Esc` 关闭面板；面板可见时自动聚焦输入框；展开长答案会保持当前阅读位置。

## 副作用与风险

- 每次旁问**多花一次模型调用**（fork 当前对话）。
- **会创建一个子会话**并随后归档。若归档不可用，子会话会留在会话列表里 —— 答案本身不受影响。
- **会写** `<dataRoot>/btw/<父会话id>.jsonl`（每会话最多 `historyLimit` 条；默认 50，可配 1–200；原子替换）。同一会话的两次旁问不会互相覆盖：host 进程内按文件串行化写入。**绝不**把主对话内容复制到磁盘。
- **只读由进程内的工具 guard 强制**，不靠提示词：guard 挂在旁问子代理自己的作用域上，它发起的工具调用会带着面向模型的原因被拒，其它会话不受影响。作用域机制已对照 DSH 0.2.2-rc.5 的宿主源码确认（`tools.guard()` 注册到调用方 scope、`checkGuards()` 只看 `[global, ...agent scope 链]`）；本版**没有**重跑真机的端到端拒绝（**待 live 验证**）。
- **超大上下文会话会给成本量级提示**：父会话上下文超过 250K tokens（宿主 contextPressure）时，面板顶部显示一行警告（预计为上下文的 0.75–1.2 倍）并带上本会话上次旁问的真实 prompt 总量，`/btw` 结果末尾也会追加同一提示；**不阻断**提问。
- **可选的 bounded 模式（`boundedContext`）**：上下文超过 400K 时，可以让旁问跑在 spawn 子代理上，只带最近 12 条 user/assistant 消息（单条 ≤700 字、总 ≤4000 字）+ 本次问题。成本 = digest + 宿主子代理固定开销（几万 tokens；本机重载 profile 实测约 119K，对比 full fork 的 762K），但会丢较早上下文，答案标记 `bounded`；默认关，且该模式不复用父会话前缀缓存。它关着时插件**完全不读**父会话事件（旧版会先把整棵事件数组物化一遍，只为取最后 12 条）。

## 卸载与残留

卸载插件只删**代码**，不会删它写过的数据：

- `<dataRoot>/btw/<父会话id>.jsonl` —— 旁问历史，一个父会话一个文件；
- `<dataRoot>/btw/settings.json` —— 在**设置 → 旁问**里保存的设置。

`<dataRoot>` 默认 `~/.dsh`（可用插件配置 `dataRoot` 改）。卸载后想彻底清理，删掉 `<dataRoot>/btw/` 即可。旁问还会在宿主自己的会话存储里留下**已归档的子会话** —— 那属于 DSH 的数据而不是本插件的，用宿主的会话列表管理。
