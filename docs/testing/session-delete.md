# session-delete 测试清单

> 目的：把「怎么证明这个插件能安全删会话」写成可执行的步骤，而不是靠感觉点两下。
> 三层结构：**自动化 → 启动冒烟 → GUI 手测**。前两层每次提交都跑，第三层每次发版和每次 DSH 升级都跑。

## 0. 测试环境

**永远优先在临时 profile 上跑破坏性用例**，不要拿真实数据试：

```bash
# 1) 打包（link: 安装不可用，见 docs/runtime `6.9）
cd packages/session-delete && pnpm pack --pack-destination /tmp

# 2) 造一个隔离的 DSH_HOME：复制 profile + 会话 + 存储
H=/tmp/dsh-test
rm -rf $H && mkdir -p $H/profiles
cp -R ~/.dsh/profiles/desktop $H/profiles/sdel
cp -R ~/.dsh/sessions $H/sessions
cp -R ~/.dsh/storages $H/storages
DSH_HOME=$H dsh plugin --profile sdel install
DSH_HOME=$H dsh plugin --profile sdel add /tmp/kangyishuai-dsh-session-delete-0.1.0.tgz

# 3) 启动（端口 0 = 随机，--no-open 不弹浏览器）
DSH_HOME=$H dsh --profile sdel --port 0 --no-open
```

**观测点**（每次操作后都可以对照）：

| 位置                                    | 看什么                                                       |
| --------------------------------------- | ------------------------------------------------------------ |
| `$H/session-trash/audit.log`            | 每次 plan/trash/restore/purge 一行 JSON，含 result 与 detail |
| `$H/session-trash/journal/`             | 正常应为空；非空说明有未完成/失败的操作                      |
| `$H/session-trash/<entry>/meta.json`    | schema、sessionId、title、bytes、workspaceIds、originPath    |
| `$H/sessions/<projectKey>/<sessionId>/` | 删除后应不存在；恢复后应回来                                 |
| `$H/storages/workspace.json`            | `archivedSessionIds` / `pinnedSessionIds` 不应残留已删 id    |

真实桌面版验证只需把上面的 `DSH_HOME` 去掉、profile 换成 `desktop`，但**先备份** `~/.dsh/sessions`。

> **实测踩到的三个坑**（2026-11-13 想在不打扰正在运行的桌面版的情况下复测 0.5.0 时）：
>
> 1. `open --env DSH_HOME=...` 在 app 已经运行时会被拒绝（`Application ... was already running and so the additional environment variables could not be set`）——
>    要换 DSH_HOME 就必须先退出 app。
> 2. 直接 `exec` 那个 Mach-O 会当成 node（本机 shell 里有 `ELECTRON_RUN_AS_NODE=1`），
>    报 `bad option: --remote-debugging-port`；确实要直连二进制就先 `env -u ELECTRON_RUN_AS_NODE`。
> 3. 用「临时 DSH_HOME + `--user-data-dir=<tmp>`」起第二个实例**能起来、CDP 也通**（单实例锁按 userData 分），
>    但全新的 Electron userData 没有登录态，页面停在 welcome/登录页，主界面根本不挂载（插件的样式/入口都看不到）。
>    所以这条「隔离复测」路线走不通——桌面回归**必须**在真 profile 上、把新版装好并重启后跑。

### K. Agent 工具（session_delete）

| #   | 优先级 | 步骤                              | 预期                                     |
| --- | ------ | --------------------------------- | ---------------------------------------- |
| K1  | P0     | 让模型调用 action=plan            | 返回影响面摘要 + token，**不删任何东西** |
| K2  | P0     | 用 token 调用 action=delete       | 会话进回收站，回执 operator=agent        |
| K3  | P0     | 模型试图删除自己所在会话          | 明确拒绝（caller-session）               |
| K4  | P1     | 重复使用同一 token / 超过 2 分钟  | 拒绝（invalid-token / token-expired）    |
| K5  | P1     | plan 之后会话被改名/改动再 delete | 拒绝（stale-plan），要求重新 plan        |

> K1–K5 的状态机已在 `test/agent-tool.test.js` 覆盖；注册状态、以及「宿主侧删除后 UI 自动刷新」
> 由 `pnpm smoke:session-delete` 覆盖（它会直接删掉临时 home 里的一个会话目录来模拟外部删除）。
>
> **K3/K4/K5 的手工测法**（模型不用凭记忆，一条指令里做完）：
> - token 只能一次：`先 plan，然后用同一个 token 连续 delete 两次` → 第二次应返回 `invalid-token`；
> - 过期：`plan 之后等 2 分钟以上再 delete` → `token-expired`；
> - 会话变化：`plan 之后先让我把目标会话改个名/发一条消息，再 delete` → `stale-plan`。
> 真实模型调用可以跑：

> 以下命令都在**仓库根目录**执行（`pnpm` 需要找到根 `package.json`）；不在仓库根时可直接
> `node <repo>/scripts/smoke-agent-tool.mjs`。

```bash
# 方式一：官方路由
cd <repo>
DEEPSEEK_API_KEY=<key> pnpm smoke:agent-tool

# 方式二：复用桌面版的 provider 配置（从 ~/.dsh/profiles/desktop/cordis.patch.yml 抽出模型块）
DSH_AGENT_TOOL_PATCH=/tmp/model-overlay.yml ZHINAO_API_KEY=<key> pnpm smoke:agent-tool
````

> 脚本会把 `~/.dsh/.credentials.yaml` 复制进临时 home；但 provider 的 `apiKeyEnv`
> 仍需要环境变量，所以方式二还要额外 export 对应 key。

> 它会临时建 headless profile、安装当前源码、让模型走一遍 plan→delete，并断言审计里出现
> `operator=agent`；没有 key 时打印 SKIP。
>
> **真机结果（2026-11-05）**：通过。headless 组合没有 workspaceRegistry，能力探测落在
> `minimal` 档：会话目录、投影缓存、宿主内存条目正常清理；归档/置顶/工作区记账/spill
> 标记为 skipped 并在回执里逐项列出，模型据此说明「这些接口当前宿主不提供」。

## 4. 回归节奏

- **每次提交**：`pnpm verify` + 冒烟 4 条。
- **每次发版**：冒烟 + P0 用例全跑（A1/A2、B1/B2、C1/C2/C3、D1/D2/D3、E1、F1、G1/G2）。
- **每次 DSH 升级**：先跑 `pnpm probe:runtime`（解析 app.asar 核对宿主包/API/slot，16 项），
  再跑 P0 + E4 + F1（降级路径最容易被升级打破）。换宿主版本后还要新建
  `docs/runtime/<新版本>.md`。

## 5. 已知未覆盖 / 风险

1. **client 交互只覆盖主链路**：`pnpm smoke:session-delete` 覆盖删除/恢复/彻底删除，但键盘、角标、只读模式仍靠手测。
2. **宿主内部契约**：`detachEntered`/`storageDomain`/`session-stop` 在真实宿主上只验证过「删除后刷新不复活」，没验证失败分支。
3. **Windows**：`EBUSY` 重试、命名信号量路径未测（当前只在 macOS 上验证）。
4. **多窗口/多 profile 并发**：审计与 journal 的并发写未在真实多窗口下压测。
