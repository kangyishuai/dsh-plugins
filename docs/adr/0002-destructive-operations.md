# 0002. 破坏性操作的统一处理方式

- 状态：已接受
- 日期：2026-11-04
- 涉及：repo（所有会删除或改写用户数据的插件）

## 背景

DSH 的持久化 seam 不提供删除接口，部分插件（比如 session-delete）只能直接操作 `~/.dsh/` 下的文件。删错了就是不可恢复的数据丢失，而且 DSH 内部格式会随版本变化。

## 决定

所有会删除或改写用户数据的插件都必须做到：

1. **默认移入回收站**，而不是硬删。回收站放在 `~/.dsh/` 下、以插件命名的独立目录（如 `~/.dsh/session-trash/`）。硬删只能作为显式选项，或者用于「清空回收站」。
2. **必须有确认框**，明确写出影响面：数量、大小、是否 live、能否恢复。
3. **支持 dry-run**：可以只列出将要做什么，不实际执行。
4. **写审计日志**：通过 `ctx.logger` 记录操作对象、结果和失败原因。
5. **只处理认识的东西**：按已知模式扫描和匹配，遇到不认识的条目保留并告警，绝不 `rm -rf` 上层目录。
6. **数据根目录可注入**，测试在临时目录里覆盖删除逻辑。

## 影响

- 每个这类插件都要多写回收站和恢复逻辑，换来的是出错可以挽回
- 回收站会占磁盘空间，插件需要提供查看和清空的入口
