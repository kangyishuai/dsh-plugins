# ADR 0007：session-rewind 的文件还原——写前快照 + 救援点，不做真 undo

- 状态：已接受
- 日期：2026-11-06
- 关联：[ADR 0006](0006-session-rewind-architecture.md)、[ADR 0002](0002-destructive-operations.md)

## 背景

[ADR 0006](0006-session-rewind-architecture.md) 的 v1 明确「只回溯对话、不碰工作区文件」。
产品确认后（2026-11-06），回溯入口要与 Claude Code `/rewind` 对齐：确认框里提供
**「仅回退对话」/「回退对话和文件」** 二选一，文件模式要还原被撤回轮次改过的文件。
同时用户明确：**不做宿主内部 patch 的真 undo/redo**（除非接受内部 patch，当前不接受）。

这带来两个必须回答的问题：

1. 文件还原本身是破坏性写操作，怎么保证可恢复、不误伤？
2. 没有 undo 的情况下，文件模式的安全底线是什么？

## 决策

1. **只追踪写类工具，不追踪 shell/脚本/子代理。** 只处理 `write` / `edit` / `apply_patch`
   对当前会话 cwd 的改动；git 与普通目录一视同仁；`bash` 删除/重定向、外部进程、子代理的
   改动不在范围内（README 与确认框明示）。这样覆盖率可控、误伤面最小。
2. **写前快照 + 内容寻址存储。** 每次工具执行前读取目标文件（或使用工具结果自带的 before），
   按 anchor（最近一条真人用户消息的 seq）记一条 entry；内容按 sha256 去重存
   `<DSH_HOME>/session-rewind/blobs/`。单文件上限 8 MiB，超限/符号链接/`.git`/`node_modules`
   直接跳过并告警，绝不静默假装还原。
3. **恢复前必须建救援点；失败可回滚。** 执行文件模式时先把当前受影响文件复制成 rescue；
   rescue 失败就一个字节都不动。恢复逐文件写回/移入回收站，写后校验 sha256；任一文件失败
   用 rescue 回滚已应用的文件。救援点保留最近 5 份，可在回溯面板里手动恢复
   （恢复救援点本身会先建一份 rescue-of-rescue）。
4. **删除走回收站，不硬删。** 目标消息之后新建的文件在回溯时移入
   `<DSH_HOME>/session-rewind/trash/<session>/<auditId>/`，而不是 `rm`。回收站与救援点都有
   保留策略（20 个操作 / 5 份 / 1 GiB 软上限），卸载保留数据。
5. **外部改动冲突时整体拒绝。** 恢复前逐个比对「当前内容」与「最后一次记录的 after」；
   任何不一致（被外部修改、缺失、意外出现）都整体拒绝，`details.conflicts` 列出路径，
   不做部分覆盖。这是对「用户手改优先」的硬约束。
6. **没有真 undo，就不假装有。** 会话回退后不能「取消回退」把模型上下文恢复；文件模式也没有
   「撤销本次还原」按钮。面板里能看的是：审计记录、幽灵历史（被撤回的消息文本）、救援点
   （文件级手动恢复）。要真正撤销，用户仍有 git 仓库或 rescue 目录。
   （生态里 gulagala001 等插件实现了 undo，但代价是宿主内部 patch/恢复事务；本插件按
   用户决定不接受这部分维护风险。）
7. **顺序：先校验 → 建救援点 → 追加会话 marker → 写文件。** 文件模式的冲突/救援失败发生在
   marker 之前；marker 一旦写入，会话回退即生效，文件失败逐项报告但不回滚会话（审计里同样
   记录 partial 结果）。

## 后果

- 好：文件模式有明确的覆盖范围、可解释的跳过原因、可回滚的失败路径；不依赖 git；
  与「只追加会话日志」的 v1 安全叙事兼容；数据都在 `session-rewind/` 下，可整体清理。
- 代价：有一个快照引擎要维护（8 MiB 上限、去重、GC、软上限、跨平台路径）；不追踪 shell
  改动会漏掉一部分文件变化；没有 undo 意味着误操作只能靠救援点/审计/手动恢复；
  Windows 分隔符与权限位未验证（按 POSIX/macOS 实现）。
- 明确不做：整工作区快照、git 对象库复用、逐文件 diff 预览、跨会话批量回溯、真 undo/redo。

## 备选方案

- **不实现文件模式**：维护成本最低，但与确认后的产品范围冲突。
- **只依赖 git**：不满足非 git 目录；且 rewind 的语义是「回到消息之前」，不是「回滚提交」。
- **实现真 undo**：需要 patch 宿主 `deriveMessages` 或做恢复事务，DSH 升级即可能碎；否决。
- **shell 侧改动也追踪**：需要解析/审计任意命令，误伤面太大，且无法保证可回滚；否决。
