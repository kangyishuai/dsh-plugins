# 0008. session-rewind 的「非破坏性召回」：召回与回溯分工

- 状态：已接受
- 日期：2026-11-09
- 涉及：session-rewind

## 背景

长对话里最常见的动作不是「撤回」，而是「刚才那条我想再看一眼 / 改一句再来」。回溯能满足它，但代价大：
回溯会从模型上下文里撤掉目标消息及其后的所有内容，并追加一条 marker——用户只是想复用一句话，
却把上下文剪了。

生态里已经有 40 多个「输入框 ↑/↓ 召回」插件（调研见私有笔记 `composer-history/` 与
`market-inventory.md`），说明这个需求独立存在；但它们与本插件重叠，且普遍用 `window` keydown +
私有 DOM 选择器实现（宿主升级后静默失效）。

约束：

- 裸 `↑`/`↓` 在宿主快捷键服务里已被固定动作 `move`（菜单上下选择）登记，**不能注册**为插件快捷键；
- 输入框是 Lexical contenteditable，插件没有公开的元素句柄（私有 DOM）；
- 本插件的定位是「用户确认才改动会话」，任何自动写会话的行为都不可接受（见 ADR 0002、0006）。

## 可选方案

1. **另起一个插件做召回。** 与回溯解耦，互不影响；缺点是：与已有 40+ 竞品正面竞争、用户要多装一个包、
   两边的「输入框回填」逻辑各写一份，且 `Esc` 双击等手势会互相抢。
2. **把召回做进 session-rewind，但召回本身不碰会话。** 复用已有的输入框回填通道（`setDraft`）与
   会话日志读取（Chat 快照），召回只改草稿；回溯仍是唯一会改上下文的动作。
3. **不做。** 用户想要只能去装第三方插件，且无法与本插件的「已撤回」面板复用。

## 决定

选 **2**。边界写死为：

- **召回只替换草稿**：走 `conversation.input.for(scope).setDraft(text)`（拿不到时才退化到 DOM 通道），
  从不追加会话事件、从不发送、从不改文件；
- **历史来源是本插件自己的宿主 RPC `sessionRewind/candidates`**：它本来就在读「真人发送且仍在
  surface 上」的用户消息（新→旧，带完整文本），召回按会话缓存它的投影（上限 100 条，TTL 1.5s，
  先给旧值、后台刷新；回溯成功后立刻失效）。曾被回溯撤下的消息不在 surface 上，因此不会出现在召回里——
  它们只在面板的「已撤回」页签；
- **手势走宿主的 fixed input 通道**（`shortcuts.observeFixedInput`），不注册快捷键：裸 `↑`/`↓` 不冲突，
  输入法组合（`gesture.composing`）、是否已被别人消费（`gesture.defaultPrevented`）、焦点区域
  （`context.region`）都由宿主算好；
- **门控**：空草稿或光标在首行时 `↑` 才召回；浏览中光标在末行时 `↓` 才前进；`/`、`@` 菜单打开
  （`context.modal` 非空）与发送中（facade 的 `phase !== "plain"`）都不接管；
- **草稿暂存**：开始浏览前的草稿存起来，`↓` 越过最新一条时原样恢复（readline 的 pending line 语义）。

**不做的**：不抢 `Esc`（`Esc` 双击仍是回溯入口）、不做 ghost 补全/模型预测、不做跨会话历史、
不做 prompt 优化、不自动发送。

## 影响

- 好：用户获得「安全地翻历史」的入口，且与回溯共用同一套面板与 i18n；实现不引入新的会话写入路径，
  也不新增私有 DOM 依赖（手势来自宿主通道，历史来自已接管的 builder）。
- 代价：
  - 历史取最新的 100 条（更旧的仍在宿主日志里，用 `Esc` `Esc` 的全量候选列表或面板分页看）。
  - 首次按键要等一次本地 RPC（毫秒级）；之后走缓存，且快照过期时先给旧值再后台刷新。
  - 早期实现曾从 Chat builder 的快照里收集历史，实测在「插件装好后才打开的会话」里永远为空
    （包装器构造时拿不到会话 id，只有显式 rebuild 才拿得到），因此改为 RPC 取数。
  - 召回通过 `setDraft` 整篇替换，会进入输入框的 undo 栈：`Ctrl+Z` 会倒退着穿过召回记录。
  - `observeFixedInput` 是私有 seam，掉线时降级为「没有召回」，不影响回溯与其它功能；
    `pnpm probe:runtime` 需要补一条检查（见 docs/runtime）。
  - 与宿主「`Esc` `Esc` 停止」不冲突，但用户可能误以为 `↑` 也是回溯入口——README 需明确两者区别。
- 重新考虑的条件：宿主若公开输入框元素句柄或 draft 的 edit-range 写入（生态里
  `dsh-composer-history` 已向上游提 C1/C3），可去掉 DOM 兜底并精确控制 undo。
