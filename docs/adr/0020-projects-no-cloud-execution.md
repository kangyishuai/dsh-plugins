# 0020. projects：不做云端执行与多租户

- 状态：已接受
- 日期：2026-11-17
- 涉及：projects

## 背景

Claude 的 Projects 把线程跑在云端容器里，于是天然带「多设备、关掉笔记本也能继续」。
`projects` 面向的是 DSH 桌面版，执行发生在**本机**。设计初期考虑过要不要对齐云端形态。

## 可选方案

1. **云端容器沙箱**：对齐 Claude 的形态。需要镜像、配额、网络隔离、凭据投递、多租户隔离——
   是平台工程，不是插件能承担的事。
2. **多设备同步（L2/L3）**：自己定义远端存储 + 身份 + 单写者租约 + 冲突策略。收益低、
   面积大，且与「不做账号体系」冲突。
3. **只做本机（L1 远程访问限于文档）**：会话与工作树都在本机，远程访问只作为"看与连"的说明，
   不引入任何服务端。

## 决定

选 **3：不做云端执行、不做多租户、不做多设备同步**。

细节边界：

- **L1（远程访问单机）**：只写文档与冒烟，不新增服务端组件；
- A（常驻远端主机）与 B（SSH 直连）都**不做**；
- L2/L3（多 Host 共享项目视图）**不做**：需要身份、远端存储、单写者租约、冲突策略；
- 每线程容器沙箱**不做**：平台工程；
- 账号体系**不做**。

## 影响

- 「关掉笔记本还能继续」「多设备接续」这类能力**不提供**，README 里要写明。
- 项目上下文、线程工作树、协调器全部本地；跨设备只能靠 Git 远端本身。
- 代价是迁移成本：将来若要云端形态，需要重做执行层（本 ADR 会被新 ADR 取代）。
- 好处是安全面小：不需要身份系统、不需要远端存储，也不存在"谁的授权"这类跨用户问题
  （见 ADR 0019）。
