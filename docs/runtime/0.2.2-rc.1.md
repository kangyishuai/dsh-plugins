> **适用版本：DSH 桌面版 0.2.2-rc.1。** 来源：`app.asar` 与 npm 上 `@deepseek-ai/*` 包的原文、`0.2.1-rc.5` 与 `0.2.2-rc.1` 两版逐包对比、以及本机实测。

## 0. 一句话结论

0.2.1-rc.5 → 0.2.2-rc.1 对插件是**非破坏性升级**：探针 16 项全 PASS，会话日志格式仍是 v4，持久化 seam 仍然没有删除 API`session-delete` 的端到端冒烟 24/24 通过。**没有需要改代码的宿主变化。**

实测基线：`dsh --version`、`Info.plist`、`app.asar` 内 `/dsh/package.json` 三处都是 `0.2.2-rc.1`。

## 3. 版本闸门：预发布语义（**更正上一版的结论**）

`@deepseek-ai/dsh-app-boot` 里判定插件版本要求的函数，两版**实现完全相同**：

```js
function satisfies(runtimeVersion, range) {
  return (
    range.trim() !== "" && semver.satisfies(runtimeVersion, range, { includePrerelease: true })
  );
}
```

`includePrerelease: true` 意味着预发布版本参与常规范围比较。用宿主自带的 semver 7.8.6 实测（✓ = 满足）：

| range                   | 0.2.1-rc.5 | 0.2.1-rc.6 | 0.2.1 | 0.2.2-rc.1 | 0.2.2 | 0.2.3-rc.1 | 0.3.0-rc.1 |
| ----------------------- | :--------: | :--------: | :---: | :--------: | :---: | :--------: | :--------: |
| `>=0.2.1-rc.5 <0.3.0`   |     ✓      |     ✓      |   ✓   |     ✓      |   ✓   |     ✓      |     ✓      |
| `>=0.2.1-rc.5 <0.3.0-0` |     ✓      |     ✓      |   ✓   |     ✓      |   ✓   |     ✓      |     ✗      |
| `^0.2.1-rc.5`           |     ✓      |     ✓      |   ✓   |     ✓      |   ✓   |     ✓      |     ✗      |

**结论更正**：[0.2.1-rc.5.md](0.2.1-rc.5.md) §6.7 与 [ADR 0005](../adr/0005-dsh-version-compatibility.md) 里的表是拿**不传 options 的 `semver.satisfies`** 算的，和宿主真正的判定不一致，因此「任何新 patch tuple 的预发布都不满足现有多数 range」这个说法**不成立**：`>=0.2.1-rc.5 <0.3.0` 接受 0.2.2-rc.1。

两个仍然成立的细节：

- 想**排除**下一个 minor 的预发布，上界要写 `<0.3.0-0`；`^0.2.1-rc.5` 会自动带上这个 `-0` 上界。
- 声明 `engines.dsh` 依然是「承诺」而非「白送」：range 内的任何版本都会被放行，包括没验证过的。是否声明仍按 ADR 0005 的验收节奏决定。

### 启动期拒绝的形态（本版读到的事实）

- 拒绝发生在 **composition 边界**：被拒的插件行在启动器自己的 composition 里变成 `disabled: true` 的游离行，**不会 import 它的模块**；被拒的 bundle 直接跳过，并列入 `skippedBundles`。
- 豁免写在 profile 自己的 `compatibility.json`（不是 `package.json`），键是精确的 `包名@版本` → 精确的 DSH 运行时版本列表。
- **插件升级或 DSH 升级都不会继承豁免**（原文："neither a plugin upgrade nor a DSH upgrade inherits permission"）。所以升级完要重新确认。
- 没有 `compatibility.json` 就等于没有豁免。本机 desktop profile 目前没有这个文件，也没有插件被拒。

## 4. 会话日志格式

- 常量在 `@deepseek-ai/dsh-session`：`SESSION_FORMAT_VERSION = 4`，两版相同。
- 文件名由 JSONL 后端的 `generationLogFilename(version, compression)` 生成，磁盘上仍是 `session.v4.jsonl.zstd`；`locate(meta)` 仍返回 `{ kind: "jsonl", path }`。
- 因此「按目录删除」的策略继续有效，插件不需要知道格式版本；继续**不要写死文件名**。

## 7. 这次踩到的坑

1. **asar 数据区有 4 字节对齐填充**。文件数据的起点是 `16 + align4(jsonLength)`，不是 `16 + jsonLength`。本版 `jsonLength = 5748746`，真实起点 `5748764`——少算这 2 字节会让每次读文件整体偏移：`package.json` 解析失败（版本号变 `?`），而以「搜特征」为主的检查恰好还能命中，于是**探针一边报错一边显示全绿**。仓库的 [probe-runtime.mjs](../../scripts/probe-runtime.mjs) 已修。
2. **别用裸 `semver.satisfies` 推算闸门**。宿主传了 `includePrerelease: true`，两者对预发布的结论可能相反（见 §3）。
3. 上一版记录的坑仍然有效：client 半要刷新页面、仓库外直接 `import('@deepseek-ai/dsh-*')` 会 `ERR_MODULE_NOT_FOUND`、`link:` 安装无法激活、Typert Remote 方法必须声明在导出类自身原型上、headless 组合没有 `workspaceRegistry`。

## 8. 下次升级要做什么

1. 升级前先跑一次 `pnpm probe:runtime` 留基线，升级后立刻再跑一次，对比差异。FAIL 行会直接写出
   「这条 seam 没了会导致哪个功能静默消失」，末尾还有一份「升级影响（按功能）」清单。
2. 新建 `docs/runtime/<新版本>.md`，按本文件的表逐项核对，**不要覆盖**旧版本记录。
3. 重点看三件事：`SESSION_FORMAT_VERSION`、`sessionPersistence` 是否终于有了删除 API、`satisfies` 的 options 有没有变。
4. 跑 `pnpm smoke:session-delete`（临时 `DSH_HOME`，不碰共用 profile），再在桌面版里确认插件状态条不是只读模式。

## 9. 追加核实（2026-11-06，为 session-rewind 勘察）

> 来源：`app.asar` 内 `dsh-session`、`dsh-client-ui-chat`、`dsh-client-ui-conversation`、
> `dsh-client-ui-renderer`、`dsh-client-shortcuts`、`dsh-api-session-controller` 的源码原文。
> 标注 **【源码】** 的结论来自随包发布的 JS；「GUI」列为真机验证状态（smoke 覆盖后更新）。

### 9.1 会话 surface 的 `replace`：只遮蔽、不删日志

- **【源码】** `Session.surface.nodes` 是模型可见节点的有序 seq 数组。消息类事件
  （`system/message`、`developer/message`、`user/message`、`assistant/message`、`tool/result`）
  必须带 `surfaceOp`：`"append"` 或 `{op:"replace", startSeq, endSeq}`。
- **【源码】** `replace` 的 `startSeq`/`endSeq` 必须是当前 surface 里已存在的节点；新事件自身
  成为一个节点，替换掉闭区间内的旧节点。`sourceEventSeqs` 必须**完整覆盖**被遮蔽的 surface 节点，
  否则 append 抛错。`/compact` 就是这条路径（`compaction/summary`）。
- **【源码】** surface 的推导/校验在 `dsh-session` 的 `foldSurface` / `SurfaceManager`；客户端的
  system-prompt 检查（`inspectSystemPrompt`）也按同样的 replace 规则折叠。
- **【源码】** `Session.append(type, data, opts)`：`data` 必须无损 JSON；`opts.surfaceOp`、
  `opts.sourceEventSeqs` 会被快照；返回落库事件（含分配好的 `seq`/`time`）。store 拥有的会话
  必须已 announce 才能 append，且 append 期间不可重入。
- **结论**：插件可以追加一条 `user/message` 标记，用 `replace` 把「目标消息及其后的全部
  surface 节点」换成一个占位节点，从而只截断模型上下文；日志本身只增长一条，历史完整保留。

### 9.2 marker 的身份字段可以放在 `source` 里

- **【源码】** `assertMessageEventShape` 只要求 `source.kind` 是非空字符串（`system/message` /
  `assistant/message` / `tool/result` 另有各自约束，`user/message` 没有），未知字段不校验、不删除；
  持久化与 `adoptSessionEvent` 都会保留额外字段。
- **【源码】** 客户端 Chat 的 user 节点 data 里带 `source`（`dsh-client-ui-chat` 的
  `messageDefinition.start` 返回 `source: event.data.source`）；会话事件 wire schema 的
  `data` 是 `z.json()` 透传，不裁剪字段。
- **【源码 + 实测】关键限制**：`messageDefinition.match` 只接受 `isAppendSurfaceEvent`
  （`surfaceOp === "append"`）的 user/message，而回溯 marker 是 `replace`，所以 **marker 不会
  在 Chat 快照里生成节点**，被遮蔽的旧节点也照常渲染（客户端刻意把 append 事件当人类
  transcript）。因此「界面隐藏」不能靠扫 marker 节点，必须由宿主给出裁剪区间。
- **结论**：客户端调用宿主 `sessionRewind/cuts`（读 live session 事件里的 marker）拿
  `[{targetSeq, markerSeq}]`，按会话缓存后再包装 Chat builder。marker 的 `source.targetSeq`
  仍保留，作为审计信息与未来若 Chat 开始渲染 replacement 节点的前向兼容。

### 9.3 Chat builder 原生支持 `visibility: "hidden"`

- **【源码】** Chat 节点带 `visibility: "visible" | "hidden"`；`dsh-client-ui-chat` 的
  `chat-visibility` 与快照构建会把 hidden 节点排除出 `order`、Turn 导航与分组，但节点留在
  store 里（`nodes.values()` 仍能读到）。
- **【源码】** `uiConversation.views` 是命名 view 注册表；`dsh-client-ui-chat` 注册的 `chat`
  view 定义有 `create()`，返回带 `empty` / `replace({nodes,timeline,changedTurns})` /
  `apply({upserts,...})` / `publish` / `groupInput` 的 builder。替换这个 `create` 是包装
  Chat 快照输入的可行 seam（私有，非公开扩展点）。
- **【源码】** `uiConversation.binding(id).target("chat")` 返回 `{getSnapshot,subscribe}`；
  `binding(id).rebuild?.()` 可强制重建。

### 9.4 `conversation.chat.node` 是键控槽，槽位账本可接管渲染器

- **【源码】** slots 服务由 `dsh-client-ui-renderer` 提供（服务名 `slots`）。注册的 keyed slot
  在账本里以 `entries(slot)` 暴露，条目含 `component` 与 `options.key`；`subscribe(slot, cb)`
  监听注册变化，`component` 可原地替换。
- **【源码】** `dsh-client-ui-chat` 为每种节点 kind 注册一个 `conversation.chat.node` 条目
  （`options.key` 为 `user` / `steering` / `assistant-step` / …）。user 行渲染器返回的元素
  本身没有 `actions` 构造器；`UserMessageNodeView` 内部构造的 `MessageIconActions` 元素才带
  `clock`/`extraActions` prop，官方 `MessageIconActions` 在复制按钮后渲染 `extraActions`。
- **【源码 + 实测】** 会话级槽组件能拿到 `sessionId`（`dsh-client-ui-session` 的 provide 里
  `props: ["sessionId"]`）。
- **结论**：接管 `key === "user"` 的组件，先调用官方 renderer，再 clone 行元素，找到其内部
  `MessageIconActions` 子元素（以 `clock` prop 识别）并追加 `extraActions`，即可在复制按钮旁
  插入按钮（形状不符时原样返回）。

### 9.5 输入框 facade 与键盘

- **【源码】** `ctx.get("conversation").input` 是 `SessionInputResolver`：
  `for(scope)` / `shell(id)` 返回带 `setDraft(text)`、`focus()`、`addAttachments(ids)` 的 façade；
  `scope` 来自 `ctx.sessions.scope(sessionId)`。`setDraft` 走宿主自己的 Lexical 编辑器整篇替换。
- **【源码】** `ctx.get("shortcuts")`（`dsh-client-shortcuts`）提供 `registerFixed(command)` 与
  `observeFixedInput(listener)`；listener 收到 `{type, gesture, context, consume}`，
  `gesture` 含 `code/repeat/composing/control/alt/shift/meta/defaultPrevented`，`context` 含
  `modal/region/target`。内置的「Esc Esc 停止」也走同一通道：运行中会先 `consume()`，之后注册的
  listener 看到 `defaultPrevented === true`。`stopSequenceMs`（默认 500ms）是可用的双击窗口。

- **【源码 + 实测，v3 召回新增】** `observeFixedInput` 的 listener 收到的是**每一个 keydown**，
  不只固定动作命中时：`dsh-client-shortcuts` 的 `installKeyboard` 在
  `shortcuts.dispatch(...)` 之前无条件调用 `fixed?.(input)`。因此裸 `ArrowUp`/`ArrowDown`
  （它们同时是固定动作 `move`）也能被观察者收到，且 `context.region` 已经把焦点元素分成
  `editable` / `page` / `terminal`，`gesture.composing` 已经算好输入法组合。
  这是「插件想接管输入框方向键、又不能注册快捷键（裸 ↑/↓ 被 `move` 占用）」时的正确入口：
  旁听 + 命中时 `consume()`（内部就是 `event.preventDefault()`），比自挂 `window` keydown
  再猜私有 DOM 选择器更稳。注意 `consume()` 只阻止默认动作，不会 `stopPropagation`。
- **【源码】** 会话根元素的 DOM 标记 `data-conversation-session` 由
  `dsh-client-ui-conversation` 的 Chat 列渲染；配合 `context.target.closest(...)` 可以判定
  「这是哪个会话的输入框」，不需要猜输入框本身的私有 class。

### 9.6 宿主 agent 状态

- **【源码】** `ctx.get("agents")`（`AgentRegistry`）有 `get(sessionId)`；Agent 有 `status`
  （`"idle"` 等）与 `cancel({kind:"user"})`。子代理会话可由 `session.header.origin ===
  "subagent"` 或 `delegationDepth > 0` 判定。
- **【源码】v2.1 补充核实（`@deepseek-ai/dsh-agent-loop/lib/index.js`）**——「停下运行中的回合
  再回溯」需要的四个成员都存在：
  - `get status()`：`phase.kind` 为 `idle` / `maintenance` 时返回 `"idle"`，其余 `"running"`；
  - `cancel(cause, options)`：`options.keepInbox === true` 时**不清空队列**，并 abort 当前阶段的
    signal；不传则是「丢弃队列里的待投递消息」；
  - `whenIdle()`：返回 `Promise<void>`，在驱动结束（含 maintenance）后 resolve；
  - `inbox.nextStep`（getter，待投递的插话消息）与 `inbox.remove(messageId)`。
    做法：`cancel({kind:"user"}, {keepInbox:true})` → `await whenIdle()`（带超时）→ 丢弃
    `inbox.nextStep` 里残留的插话，然后才求 surface 并 append marker。**必须先停稳再求值**：
    运行中的回合会在我们求值与 append 之间继续追加事件，marker 的 `replace` 范围随之失效。

### 9.7 GUI 验证结果（2026-11-06，`pnpm smoke:session-rewind`）

临时 `DSH_HOME`（复制 desktop profile + 真实会话）里启动真实宿主、装当前源码打出的包，用
ego-browser 走完整链路，**17/17 断言通过**，覆盖：

2. 空闲会话 `Esc` `Esc` → 候选对话框（宿主全量日志，不只当前加载窗口）→ 选一条 → 同样的效果；
3. 页面重载、切走会话再切回后，被撤回的行仍然隐藏（宿主 `cuts` 兜底路径成立）；
4. 直接解压临时目录里的 `session.v4.jsonl.zstd` 验证：原始用户消息一条没少（只追加），

### 9.8 文件写工具与工具事件（session-rewind 文件模式用）

- **【源码】** `dsh-tool-fs` 注册 `write` / `edit` / `apply_patch`（`read` 不写）。三者结果值都带
  before/after：
  - `write` → `{path, operation: "create"|"update", before: string|null, after: string}`；
  - `edit` → `{path, before, after, ...}`（0.2.2-rc.1 已带完整 before/after，无需工具前再读）；
  - `apply_patch` → `{phase:"commit", cancelled, operations:[{index,kind:"add"|"update"|"delete"|"move",
    path, destination?, status, changes?:[{path,before,after}]}], affectedPaths}`。
- **【源码】** 工具执行生命周期是 waterfall：
  - `tools/execute`：`(exec, next) => Promise<result>`，在 `next()` 前可抓 before；
  - `tools/post-execute`：`(exec, result, next) => Promise<decision>`，成功写入后提交记录；
  - `tools/result`：emit，正常与抛错路径都会触发，适合兜底清理 pending；
  - `exec` 含 `name`、`args`、`callId`、`agent`（`agent.session`）。
- **【实测】** `write` 对超过 8 MiB 的 before/after 仍然返回完整字符串；插件侧必须自己做上限，
  否则会把大文件读进内存/快照。本插件按 8 MiB 跳过并告警。
- **结论**：文件模式可以完全用工具结果拿到权威 before/after；`bash`/脚本改动没有这样的事件，
  这也是本插件不追踪它们的直接原因。

### 9.10 插件注册 agent 工具（`tools.register`）的形状要求

- **【源码 + 实测】** `ctx.inject(["tools"], scope => …)` 里的 `scope.tools.register(definition)`
  接受**普通对象**（不需要 `@deepseek-ai/dsh-tools` 的 `defineTool`，插件本来也不能依赖它）：
  `{ name, description, parameters, output: { schema, render(args, value) }, execute(args, exec) }`。
- `parameters` 与 `output.schema` 必须是**标准 JSON Schema**，不是 `defineTool` 那种
  `required: true` 的属性级写法；`output.schema` 还会在返回时校验值。
- 受支持关键字是**子集**：`type` / `oneOf` / `properties` / `required`（字符串数组）/
  `additionalProperties` / `items` / `enum` / `const` + 注解。**`minimum` / `maximum` 不支持**，
  传了会抛 `JsonSchemaError`（`register()` 里被 try/catch 吞掉的话，表现为「工具静默不存在」）。
  区间校验请在 execute 里自己夹紧。
- `execute(args, exec)` 里 `exec.agent?.session?.id` 拿到会话 id，`exec.signal` 是中止信号。
- 校验工具定义的一个省事办法：把宿主 `@deepseek-ai/dsh-tools` 的 `assertSupportedJsonSchema`
  单独拿出来跑（本次就是靠这个在提交前抓到 `minimum` 不支持）。
- 工具注册在 host 半，**改动后要重启 DSH**；本插件的「设置 → 诊断」会显示是否注册成功。

### 9.11 回溯**不会**回滚的会话状态事件

会话日志里的这些事件是「状态投影」，不属于模型可见的 surface。`surfaceOp: replace` 只改
surface，所以被撤回区间里的这些事件在回溯后**依然生效**：

`plan/mode`、`goal/change`、`todo/write`、`model/selection`、`permission/preset`、
`sandbox/mode`、`agent-preset/selected`、`schedule/change`、`working-directory/change`。

（完整列表见 `@deepseek-ai/dsh-session` 的 `KNOWN_SESSION_EVENT_TYPES`。）本插件据此在确认框里
提示「回溯只撤回对话、不回滚这些状态」；只读事件类型与次数，不解析它们的 payload 形状。

### 9.13 ego-browser 用的是**用户真实浏览器 profile**（清 cookie 必须按 domain 限定）

**踩到的坑**：冒烟脚本早期用 `Network.clearBrowserCookies` 清掉临时宿主的 `dsh-auth` cookie，
否则请求头会累积到 HTTP 431。但这个命令清的是**整个 profile** —— 也就是用户日常在用的
ego-browser（里面 `.github.com`、`.claude.ai` 等真实登录态），会把人的登录全踢掉。

**正确做法**：只删 host 属于 loopback 的 cookie：

```js
await page.cdp("Network.enable");
const all = await page.cdp("Network.getAllCookies");
const cookies = Array.isArray(all) ? all : (all?.cookies ?? []);
for (const c of cookies) {
  const domain = String(c.domain || "").replace(/^\./u, "");
  if (domain !== "127.0.0.1" && domain !== "localhost" && domain !== "[::1]") continue;
  await page.cdp("Network.deleteCookies", { name: c.name, domain: c.domain, path: c.path || "/" });
}
```

实测：本机 22 个 cookie 里只有 2 个属于 `127.0.0.1`；按上面过滤后 `removed=2`、
真实站点 cookie 数量前后一致（3 → 3）。仓库里 `smoke-session-rewind.mjs` 与
`readme-shots-session-rewind.mjs` 都已改成这种定向清理，并会打印 `SMOKE_COOKIES {removed,total}`。

**顺带**：`Page.captureScreenshot` 产出的 PNG 带 `eXIf` 块（sips 裁剪会写入时间戳一类元数据）。
进公开仓库的截图应剥掉 `eXIf/tEXt/iTXt/zTXt/tIME`——`scripts/readme-shots-session-rewind.mjs`
的 `stripPngMetadata()` 会自动做，只重算块结构、不动像素。
