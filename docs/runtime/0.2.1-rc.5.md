# DSH 0.2.1-rc.5 运行时勘察记录

> **适用版本：DSH 桌面版 0.2.1-rc.5。** 来源：`app.asar` 里 `@deepseek-ai/dsh-*` 包自带的文档，加上已安装社区插件的源码。
>
> 这份文件只记录**某个 DSH 版本上观察到的事实**，会随 DSH 升级失效。DSH 升级后请新建 `docs/runtime/<新版本>.md`，逐项核对后再改插件代码，不要直接覆盖本文件。
> 稳定的工程约定写在 [../plugin-conventions.md](../plugin-conventions.md)。

## 1. host 半可用的宿主服务

`apply(ctx, config)` 拿到的 `ctx` 上有这些服务（类型声明见 [`types/dsh-host.d.ts`](../../types/dsh-host.d.ts)）：

| 服务                     | 用途                                                                                                         |
| ------------------------ | ------------------------------------------------------------------------------------------------------------ |
| `ctx.sessions`           | 会话注册表；`flush()` 把 live 状态落盘                                                                       |
| `ctx.sessionPersistence` | 持久化 seam；`stat(id)` 读日志体积等元信息。**没有删除接口**                                                 |
| `ctx.workspaceRegistry`  | 工作区注册表；`archiveSession(id, { stopActivity })`、`unarchiveSession(id)`、`detachSession(id)`、置顶/排序 |
| `ctx.logger`             | 日志（`warn` / `info` / `error`）                                                                            |

**重要**：持久化和存储 seam 都**不提供删除 API**（官方明确说「剪枝已存储会话属于带外后端维护」）。真要删除只能直接操作文件系统，并且自己清理三处引用：归档集合、工作区归属、投影缓存。

## 2. 磁盘布局

```
~/.dsh/sessions/<workspace-key>/<session-id>/
    session.lock              # 写入方排他锁（flock）
    session.v4.jsonl.zstd     # 会话日志；vN 的 N 是格式版本，会随 DSH 升级变化
~/.dsh/storages/workspace.json        # archivedSessionIds / pinnedSessionIds / workspaceIds
~/.dsh/storages/session_projcache/    # 投影缓存 checkpoint
```

按「扫描 + 匹配已知模式」来处理，不要写死文件名（见 AGENTS.md 硬性约定 1）。

## 3. client 半的加载方式

client 半是一段以 classic script 原样下发的代码，通过 `window.__ModuleLoader__.load` 注册 factory（类型声明见 [`types/dsh-client.d.ts`](../../types/dsh-client.d.ts)）：

```js
window.__ModuleLoader__.load({
  id: "@kangyishuai/dsh-<name>",
  factory(require) {
    var module = { exports: {} };
    var exports = module.exports;

    const react = require("react");
    const jsxRuntime = require("react/jsx-runtime");
    const primitives = require("@deepseek-ai/dsh-client-ui-primitives");

    // 所有副作用（含 React.createElement）都写在这里面

    exports.inject = ["slots", "locale", "connection"];
    exports.apply = function apply(ctx) {
      // ctx.slots.inject("<slot-name>", () => ctx.slots.register({ ... }))
    };
  },
});
```

> **已核实（2026-11-04）**：factory **需要** `return module.exports`。本机已安装的 `dsh-github-picker@0.5.6` 的 client 产物以 `return module.exports; } });` 结尾，运行时依赖这个返回值。
>
> **另一处更正**：`ctx.slots.register` 的真实签名是 `register(descriptor, Component)`——第二个参数是 React 组件，descriptor 里**没有** `render` 字段。descriptor 形状（来自 picker 与 `dsh-tool-session-delete` 两个独立实现）：
>
> ```js
> ctx.effect(() => ctx.slots.inject("<slot-name>", () => ctx.slots.register({
>   name: "<slot-name>",   // 必填
>   id: "<plugin-id>",
>   order: 100,
>   label: () => t("nav"),  // 可选
>   locale: "ns",          // 可选
>   inject: () => ({ hooks, ...methods })
> }, Component)), "why");
> ```

## 4. 已验证可用的 slot

| slot                                    | 形态   | 用途                       |
| --------------------------------------- | ------ | -------------------------- |
| `sidebar.workspaces.session.menu.item`  | list   | 会话行 "…" 菜单项          |
| `sidebar.workspaces.session.row.action` | list   | 会话行尾部悬停按钮         |
| `sidebar.session.row.leading`           | list   | 行首图标（仅 idle 时渲染） |
| `sidebar.session.row.hover`             | list   | 行悬停卡片                 |
| `shell.overlay`                         | single | 全局浮层（确认框等）       |

**内置 action 的 order**（决定你的条目插在哪）：`pin` 100、`rename` 200、`fork` 300、`archive` 400（菜单）、`session-id` 450。想排在 Archive 之后、Copy ID 之前，取 `order: 420`。

**坑**：菜单项会随菜单一起卸载，所以确认框必须注册到 `shell.overlay`，由菜单项发出请求，不能用菜单内的局部状态。

## 5. 已知的坑

1. client 半没有 HMR：改完要**刷新页面**才能看到。
2. 在仓库外单独跑 `import('@deepseek-ai/dsh-*')` 会报 `ERR_MODULE_NOT_FOUND`。这些 peer 由宿主启动时通过 runtime resolution 注入，属于正常现象。
3. `desktop` profile 由 Electron 独占管理：`dsh --profile desktop --dump-config` 会被拒绝，但 `dsh plugin --profile desktop add/remove` 正常工作。
4. 想在安装前验证组合是否正确，可以把 profile 复制一份换个名字，再 `--dump-config`（Electron 只管名为 `desktop` 的 profile）。
5. 安装时如果出现 `incompatible-version` 拒绝，可以用 `dsh plugin --profile <p> allow-version <pkg@ver> --dsh-version <runtime> --accept-risk` 授权（了解风险后再做）。

## 6. 追加核实（2026-11-04，来源：`app.asar` 内的官方包 README/源码 + 已安装社区插件）

> 采集方式：用 asar 头解析 `/Applications/DeepSeek Harness.app/Contents/Resources/app.asar`，抽出 `@deepseek-ai/dsh-session-persistence`、`dsh-session-persistence-jsonl`、`dsh-workspace`、`dsh-host-webserver`、`dsh-typert-protocol` 的 README 与源码原文；并对照本机 `dsh-github-picker@0.5.6`、社区 `dsh-tool-session-delete@1.2.0` 的真实调用点。
> 标注：**【文档】** = 官方 README 原文；**【源码】** = 抽出的 .js 原文；**【社区】** = 只在该插件里见到、未在官方文档确认。

### 6.1 `ctx.sessionPersistence`（抽象 seam，已确认**没有删除接口**）

**【文档】** 官方 README 原文：

> "Nothing deletes session files — logs accumulate under root until removed externally; the seam has no deletion API."

公开方法（5 个）：

| 方法                       | 签名/语义                                                          |
| -------------------------- | ------------------------------------------------------------------ |
| `create(header, options?)` | 建新会话并取得写所有权；物理产物在首次 append/flush 时落盘         |
| `open(id, "write")`        | 取得单写者所有权；已有活跃写者时抛 `SessionAlreadyOwnedError`      |
| `open(id, "read")`         | 只读观察，不取所有权                                               |
| `stat(id)`                 | 返回 header + revision（+ `eventCount`/`sizeBytes`），**不读日志** |
| `list()`                   | 每个可见已存会话一份快照                                           |
| `flush()`                  | 后端级持久化屏障                                                   |

- **【源码】** 稳定错误类：`SessionPersistenceNotFoundError`、`SessionAlreadyExistsError`、`SessionAlreadyOwnedError`、`SessionReadOnlyError`、`SessionHandleClosedError`、`SessionOwnershipLostError`、`SessionFormatUnsupportedError`、`SessionPersistenceCorruptionError`。
- **【源码】** `SessionHandle`：`read(offset?, length?)`、`append(events)`、`flush()`、`close()`；写句柄 close 是幂等的，`session/disposed` 会触发最后一次 drain。
- **结论**：删除只能由插件做。⚠ **不要**把 `open(id,"write")` 当作「有没有活写者」的探针：它是**写路径**，对历史格式会话会生成临时文件、校验后**发布新一代 log（写盘）**并占住写所有权；放进入口预演等于「点开确认框就改了磁盘」。liveness 请用 `ctx.sessions.get(id)` + `workspace/session-activity` 两个只读信号，写者竞争交给 `rename` 的 `EBUSY/EPERM` 退避兜底。

### 6.2 JSONL 后端的文本级细节（`@deepseek-ai/dsh-session-persistence-jsonl`）

- **【源码】** `locate(meta) → { kind: "jsonl", path }`（注释：refusal-diagnostics hook，不碰文件系统）；路径由 `logPath(root, cwd, id, compression)` 计算。**这是「不要写死文件名」的官方依据**：删会话应删 `dirname(locate(header).path)`。
- **【源码】** `resolveCurrentLog(id)` 只返回当前格式代际的路径；历史代际存在时返回 `undefined`；更新的格式抛 `SessionFormatUnsupportedError`（错误里带 `{kind,path}`）。
- **【文档】** 单写者互斥：进程内 claim + 内核锁——POSIX 是 `session.lock` 上的非阻塞 `flock(2)`，Windows 用由该路径派生的命名内核信号量（无文件足迹）。崩溃的持有者锁随进程消失，`session.lock` 释放时不删除（POSIX 上手工 rm 会**丢掉互斥语义**）。
- **【文档】** 根目录由后端 `config.root` 决定，压缩由 `config.compression` 决定。

### 6.3 `ctx.workspaceRegistry`（`@deepseek-ai/dsh-workspace`）

- **【文档】** `archiveSession(sessionId)`：先问一次活动 waterfall，非空则抛 `WorkspaceActiveSessionError`（`error.activity` 按 provider 分组列出）。
- **【文档】** `archiveSession(sessionId, { stopActivity: true })`：跳过活动检查、**先写归档集合**、再派发 stop 事件——「先归档再停」是官方推荐时序，因为归档集合本身就是 provider `agent/pre-step` 的闸门。
- **【文档】** `unarchiveSession(id)`：**不做会话存在性探测**（从集合里删 id 不会引入未知 referent），所以清「归档幽灵」是安全的。
- **【源码】** 方法清单：`archiveSession(sessionId, options)`、`unarchiveSession(id)`、`pinSession(id)`、`unpinSession(id)`、`list()`、`create(dir, title?)`；Workspace 实体上 `attachSession(id)` / `detachSession(id)`。
- **【文档】** 持久化：storage domain `workspace`（version 2），`workspaces` 表 + 一个全局状态（`workspaceIds` 显示顺序、`archivedSessionIds`、`pinnedSessionIds`、可选 `defaultWorkspaceId`、可选 `pendingMutation`）。归档会**在同一次写里清掉 pin**；恢复**不会**恢复 pin。
- **【文档】** 删项目登记**不会**删目录或会话。
- **活动 seam 事件名**：【文档】`workspace/session-activity`（waterfall，问谁还在跑）、`workspace/session-stop`（parallel，请求停下）。shipped providers：Agent registry（运行中的轮次）、job registry seam（持有的后台任务）、Subagent runtime（运行中的后代）、Schedule 插件（活动提醒）。

### 6.4 `ctx.webServer`（`@deepseek-ai/dsh-host-webserver`，官方路由能力）

- **【文档】** `register(route)` 注册命名 `exact`/`prefix` 路由，`registerUpgrade(route)` 注册 upgrade 路由，都返回 disposer；同表内重复路径抛错；匹配顺序 exact → 最长前缀 → fallback。
- **【文档】** `registerFallback(handler)` 只有一个席位；无 fallback 时 404。
- **【文档】** `ctx.webServer.port` / `protocol` / `getOrigin()`；`collectIndexInjections()` / `renderIndex(html)` / `tapIndex(transform)` 是 index 注入面。
- **注意**：桌面版 Electron 以 `file://` 加载前端、fetch 走 IPC 桥，**与 Web profile 不同**；跨端插件优先走 `/api` 的 Typert Remote。

### 6.5 Typert Remote（host ↔ client 的推荐通道）

- **【源码】** `@deepseek-ai/dsh-typert-protocol` 导出：`Remote`、`RemoteError`、`RemoteScope`、`TypertRemoteService`、`bindTypertRemote`、`remoteMethods`、`principalOf`、`isTypertRemoteMethod` 等。
- **【社区/已装】** host：`class X extends TypertRemoteService`，用 `@Remote` 标记方法（TS 编译产物）；plain JS 无装饰器时按 `dsh-tool-session-delete` 的 `declareRemote()` 手工登记。
- **【已装】** client：`const remote = ctx.reflect.get("remote.<serviceName>")`，调用返回 `{ok, value, error}` 包络——**推荐用这个，而不是手搓 `ctx.connection.rpc.call("/api", "<svc>/<method>")`**。
- **【社区】** 若坚持走 `/api`：`ctx.connection.rpc.call("/api", "sessionDelete/describe", { args: { request } })` 也能工作（参考实现就这么干），但要自己处理包络与路由名。

### 6.7 插件版本闸门（`@deepseek-ai/dsh-plugin-manager`）

**【源码/类型声明】** 官方工具的说明原文：

> "Unmet DSH version requirements (`engines.dsh`, else DSH peer dependencies) block installation **and activation**. Version exemptions risk crashes and data loss: warn the user and obtain explicit permission for the exact plugin and runtime versions before granting one."

- 判定顺序：`package.json` 的 `engines.dsh`；没有则回退到插件对 `@deepseek-ai/*` 包的 **peerDependencies** 范围。
- 不满足时失败码 `incompatible-version`，错误体里带 `requirements`（只列不满足的项，key 为 `engines.dsh` 或 DSH peer 包名）。
- 豁免：`dsh plugin --profile <p> allow-version <pkg@ver> --dsh-version <runtime> --accept-risk`（需用户显式接受风险）。
- 插件管理器的说明还写明：**live profile 的变更立即生效，包括已安装包的升级**。
- **预发布 semver 陷阱（2026-11-04 用宿主自带 semver 实测）**：`>=0.2.1-rc.5 <0.3.0` 满足 0.2.1-rc.6、0.2.1、0.2.2，但**不满足 0.2.2-rc.1**——新 patch tuple 的预发布版本需要 range 里有同 tuple 的预发布比较器。所以声明 `engines.dsh` 等于承诺「每个新 patch tuple 都要跟着发版」，策略见 [ADR 0005](../adr/0005-dsh-version-compatibility.md)。

### 6.8 `dsh plugin` 命令的真实语义

- `dsh plugin --help`：**把剩余参数原样转发给 profile 目录里的 pnpm**（`add`/`remove`/`why`…），没有独立的 update 子命令；升级 = `add <pkg>@latest`（或市场 UI）。
- 因此升级后**不会**自动跑探针；兼容性必须由插件自己在激活时探测（见 ADR 0005 的 L2/L3）。


### 6.9 `link:` 安装的插件无法激活（实测踩坑，2026-11-04）

**现象**：`dsh plugin --profile desktop add "link:<repo>/packages/<name>"` 安装成功后，宿主启动时打印

```
dsh: warning: 1 entry did not activate
session-delete (@kangyishuai/dsh-session-delete): failed to import:
Error [ERR_MODULE_NOT_FOUND]: Cannot find package '@deepseek-ai/dsh-typert-protocol'
imported from .../packages/session-delete/lib/service.js
```

**原因**：`link:` 在 profile 的 `node_modules` 里只是一个符号链接，Node 会按 **realpath**（仓库目录）向上解析依赖；宿主为插件注入的 `@deepseek-ai/*` 解析只覆盖 profile 内的真实路径，于是插件的宿主包导入全部失败。**这不是我们插件独有的问题**：把本机已装的 `dsh-github-picker` 用裸 Node import 也一样报 `ERR_MODULE_NOT_FOUND`，但它在宿主里能跑，因为它的 realpath 在 profile 内。

**验证方式（同一份代码，两种安装）**：

| 安装方式                 | 已装副本 realpath                         | 启动日志                                 |
| ------------------------ | ----------------------------------------- | ---------------------------------------- |
| `link:` 仓库目录         | 仓库内                                    | `1 entry did not activate` + import 错误 |
| `add <tgz>`（pnpm 解包） | `<profile>/node_modules/@kangyishuai/...` | 无告警，正常启动                         |

**正确做法**：

```bash
cd packages/<name> && pnpm pack --pack-destination /tmp
dsh plugin --profile desktop add /tmp/<name>-<version>.tgz
```

改完代码后重新 `pnpm pack` 到同一路径、再执行一次 `add`，已装副本会更新（2026-11-04 实测：覆盖同名 tgz + 再 add 后，`node_modules` 里能读到新写入的标记行）。

**另一个限制**：`dsh --profile desktop --dump-config` 会被拒绝（Electron 独占）。验证组合是否正确，要把 profile 复制到临时 `DSH_HOME` 并改名（如 `sdel`），再 `dsh --profile sdel --dump-config`；复制后签名的 `node_modules` 链接会失效，需要在临时 home 里重新 `dsh plugin --profile sdel install`。
