# DSH 0.2.1-rc.5 运行时勘察记录

> **适用版本：DSH 桌面版 0.2.1-rc.5。** 来源：`app.asar` 里 `@deepseek-ai/dsh-*` 包自带的文档，加上已安装社区插件的源码。
>
> 这份文件只记录**某个 DSH 版本上观察到的事实**，会随 DSH 升级失效。DSH 升级后请新建 `docs/runtime/<新版本>.md`，逐项核对后再改插件代码，不要直接覆盖本文件。
> 稳定的工程约定写在 [../plugin-conventions.md](../plugin-conventions.md)。

## 1. host 半可用的宿主服务

`apply(ctx, config)` 拿到的 `ctx` 上有这些服务（类型声明见 [`types/dsh-host.d.ts`](../../types/dsh-host.d.ts)）：

| 服务                     | 用途                                                                                                         |
| ------------------------ | ------------------------------------------------------------------------------------------------------------ |
| `ctx.sessions`           | 会话注册表；`flush()` 把 live 状态落盘                                                                       |
| `ctx.sessionPersistence` | 持久化 seam；`stat(id)` 读日志体积等元信息。**没有删除接口**                                                 |
| `ctx.workspaceRegistry`  | 工作区注册表；`archiveSession(id, { stopActivity })`、`unarchiveSession(id)`、`detachSession(id)`、置顶/排序 |
| `ctx.logger`             | 日志（`warn` / `info` / `error`）                                                                            |

**重要**：持久化和存储 seam 都**不提供删除 API**（官方明确说「剪枝已存储会话属于带外后端维护」）。真要删除只能直接操作文件系统，并且自己清理三处引用：归档集合、工作区归属、投影缓存。

## 2. 磁盘布局

```
~/.dsh/sessions/<workspace-key>/<session-id>/
    session.lock              # 写入方排他锁（flock）
    session.v4.jsonl.zstd     # 会话日志；vN 的 N 是格式版本，会随 DSH 升级变化
~/.dsh/storages/workspace.json        # archivedSessionIds / pinnedSessionIds / workspaceIds
~/.dsh/storages/session_projcache/    # 投影缓存 checkpoint
```

按「扫描 + 匹配已知模式」来处理，不要写死文件名（见 AGENTS.md 硬性约定 1）。

## 3. client 半的加载方式

client 半是一段以 classic script 原样下发的代码，通过 `window.__ModuleLoader__.load` 注册 factory（类型声明见 [`types/dsh-client.d.ts`](../../types/dsh-client.d.ts)）：

```js
window.__ModuleLoader__.load({
  id: "@kangyishuai/dsh-<name>",
  factory(require) {
    var module = { exports: {} };
    var exports = module.exports;

    const react = require("react");
    const jsxRuntime = require("react/jsx-runtime");
    const primitives = require("@deepseek-ai/dsh-client-ui-primitives");

    // 所有副作用（含 React.createElement）都写在这里面

    exports.inject = ["slots", "locale", "connection"];
    exports.apply = function apply(ctx) {
      // ctx.slots.inject("<slot-name>", () => ctx.slots.register({ ... }))
    };
  },
});
```

> 待确认：factory 是否需要 `return module.exports`。模板里加了 return，第一个插件实测时请回来更新这一条。

## 4. 已验证可用的 slot

| slot                                    | 形态   | 用途                       |
| --------------------------------------- | ------ | -------------------------- |
| `sidebar.workspaces.session.menu.item`  | list   | 会话行 "…" 菜单项          |
| `sidebar.workspaces.session.row.action` | list   | 会话行尾部悬停按钮         |
| `sidebar.session.row.leading`           | list   | 行首图标（仅 idle 时渲染） |
| `sidebar.session.row.hover`             | list   | 行悬停卡片                 |
| `shell.overlay`                         | single | 全局浮层（确认框等）       |

**内置 action 的 order**（决定你的条目插在哪）：`pin` 100、`rename` 200、`fork` 300、`archive` 400（菜单）、`session-id` 450。想排在 Archive 之后、Copy ID 之前，取 `order: 420`。

**坑**：菜单项会随菜单一起卸载，所以确认框必须注册到 `shell.overlay`，由菜单项发出请求，不能用菜单内的局部状态。

## 5. 已知的坑

1. client 半没有 HMR：改完要**刷新页面**才能看到。
2. 在仓库外单独跑 `import('@deepseek-ai/dsh-*')` 会报 `ERR_MODULE_NOT_FOUND`。这些 peer 由宿主启动时通过 runtime resolution 注入，属于正常现象。
3. `desktop` profile 由 Electron 独占管理：`dsh --profile desktop --dump-config` 会被拒绝，但 `dsh plugin --profile desktop add/remove` 正常工作。
4. 想在安装前验证组合是否正确，可以把 profile 复制一份换个名字，再 `--dump-config`（Electron 只管名为 `desktop` 的 profile）。
5. 安装时如果出现 `incompatible-version` 拒绝，可以用 `dsh plugin --profile <p> allow-version <pkg@ver> --dsh-version <runtime> --accept-risk` 授权（了解风险后再做）。
