### 1.1 逐包 diff：9 个有差异，34 个逐字节相同

**方法**（下次升级照抄，比读升级指南更直接地看清「到底变了什么」）：从 npm 取本仓库插件依赖/触及的宿主包的两版 tarball，解包后逐文件比较，忽略 `package.json`（版本号必然不同）：

```bash
mkdir -p /tmp/dshdiff && cd /tmp/dshdiff
for p in dsh-session dsh-tools dsh-client-ui-chat …; do
  npm pack "@deepseek-ai/$p@0.2.2-rc.3" --silent >/dev/null
  npm pack "@deepseek-ai/$p@0.2.2-rc.5" --silent >/dev/null
  # 解包到 rc3/ rc5/ 后：diff -rq rc3/$p rc5/$p | grep -v package.json
done
```

本轮扫了 **43 个包**（六个插件 `package.json` 的 `dsh.client.inject` 全集 + `ctx` 上用到的服务所在包 + 探针覆盖的包，含 `dsh` / `dsh-base` 两个组合包）。**9 个有差异**：

| 包                               | 差异内容                                                                 | 对插件的影响                |
| -------------------------------- | ------------------------------------------------------------------------ | --------------------------- |
| `dsh-llm`                        | `LLM_FAILURE_CODES` 增加 `CONTENT_REFUSED`（`src/error.ts` 一行）        | 无（不解析失败码）          |
| `dsh-session-persistence-jsonl`  | `worker.cjs` 内嵌的失败码表同上多一行 `CONTENT_REFUSED`                  | 无（`locate()` 等未动）     |
| `dsh-web`                        | 未配置 `searchProvider` 时，按请求的模型路由优先 `deepseek-official`     | 无（插件不注册/不选提供方） |
| `dsh-base`                       | `cordis.patch.yml` 的 `web` 行删掉 `searchProvider: deepseek-search-api` | 无（组合层，不碰插件行）    |
| `dsh`                            | 只有文档：`config-catalog`、`subsystems/web`、升级指南索引 + 两个新目录  | 无                          |
| `dsh-api-remotes`                | typert 的 `sourceLocation` 行号 152 → 174（构建元数据）                  | 无                          |

### 1.2 两条官方升级指南都不涉及本仓库

从 rc.3 走到 rc.5 要读 `v0.2.2-rc.3/` 与 `v0.2.2-rc.4/` 两节（逐相邻版本一步），各 1 条：

1. **`v0.2.2-rc.3/deepseek-refusal-code`**：DeepSeek 以 `stop_reason: "refusal"` 结束流时，错误码从 `MALFORMED_RESPONSE` 改为 `CONTENT_REFUSED`。迁移步骤只要求「对 LLM 错误终止块或 `turn/end` 错误分类的代码」处理新码。本仓库六个插件的 `lib/` 与 `scripts/` 里**没有** `MALFORMED_RESPONSE` / `CONTENT_REFUSED` 出现（grep 为空），不涉及。
2. **`v0.2.2-rc.4/web-search-deepseek-model-default`**：交付组合不再固定搜索提供方（§1.1 的 `dsh-base` 那一行）；DeepSeek 模型路由上的搜索走旧版 Messages 搜索。插件不注册搜索提供方、不设置 `web.searchProvider`，也不读 `web/deepseek-search-llm-request` 事件，不涉及。

### 5.1 桌面回归的两个视图前置（本轮都踩到了）

桌面回归驱动的是**正在运行的那个桌面版**，脚本读的是「当前可见会话」。agent 在自己的会话里跑回归时，有两个前置必须自己先摆好：

1. **可见会话不能是「正在跑回合」的会话。** 否则 advisor 脚本按设计不敲键盘：`FAIL 当前会话空闲（没有正在跑的回合）` + 13 条 SKIP。做法：先把可见会话切到一个**空闲会话**再跑（切换只是换视图，不会中断正在跑的回合，[rc.3 §6](0.2.2-rc.3.md#6-本机实测2026-11-14) 已实测）。
2. **上一条桌面回归不能把页面留在别的页面。** casefile 的桌面回归结束时按了 Esc（断言「页面仍可用」），但**不会离开「案卷」主面板**；紧接着跑 btw 会因为没有 composer 而报 `FAIL 输入框左侧出现 btw 按钮`（本轮首发就是这个假红，重跑前先切回会话即 18 PASS / 1 SKIP）。串行跑多条桌面回归时，**两条之间先点回任一会话**。

这两条都不是 rc.5 的破坏性变化，是「谁在跑回归」的环境问题——写进了 §7 的升级清单。

## 6. 本轮的工具链与文档修复

### 6.1 `session-delete` 桌面回归：空回收站会假红

`pnpm smoke:session-delete-desktop --require` 在回收站**为空**时报：

```
FAIL 回收站面板保留全选与批量操作 :: {"hasTabs":false,"hasBatch":false,"text":"会话回收站回收站是空的。关闭"}
```

**根因在脚本，不在插件**：插件的回收站面板在 `entries.length === 0` 时只渲染空态（「回收站是空的。」），工具条（全选 / 恢复（n）/彻底删除）与条目行都在 `entries.length > 0` 分支里。断言把「有空条目时才存在的东西」写成了无条件断言，于是回收站空时必红；「条目：标题可读」那条更糟——`rows === 0` 被写成通过，等于**什么都没验证还报绿**。

修法（只改脚本）：用面板里的 `.dsh-sdel-row` 数量判断空/非空，空时两条记 **SKIP** 并给出原因，非空时断言不变（更严格，去掉了 `rows === 0` 的假通过）。修后实测 **16 PASS / 2 SKIP / 0 FAIL**（`pnpm gate session-delete` 不再假红）。

### 6.2 四条桌面脚本补打印门禁依赖的计数行

[plugin-conventions §6.1](../plugin-conventions.md#61-桌面端自动化测试是硬性要求) 要求桌面脚本收尾打印 `N PASS / M SKIP / K FAIL`，`scripts/gate.mjs` 的 `parseCounts()` 靠它识别「跑过但一条断言都没执行」的假绿。本轮实测：**只有 `smoke-btw-desktop` 打了这一行**；advisor / next-step / session-rewind / casefile（含修好的 session-delete）都没有打，`parseCounts()` 返回 `undefined`，`isVacuousPass()` 就永远放行——门禁的这条防线对它们等于不存在。

四条脚本已各补一行（保留原有中文汇总行不变），现在六条桌面回归都能被门禁正确判定。

## 7. 下次升级要做什么

1. 升级前跑一次 `pnpm probe:runtime` 留基线，升级后立刻再跑；先分清「能力没了」和「源码形态变了导致匹配不到」。
2. 探针里**任何带哈希的路径**都不要写死；`dist/assets/*` 用 `filePattern` 扫。
3. 想搞清楚「到底变了什么」，直接按 §1.1 对**你依赖的包**做 rc(n) vs rc(n+1) 的 tarball 逐包 diff；带 sourcemap 的 client 包先比 `sourcesContent`，再看字节。
4. 重点看三件事：`SESSION_FORMAT_VERSION`、`sessionPersistence` 是否终于有删除 API、client 半有没有换构建形态；外加新 LLM 失败码（本版是 `CONTENT_REFUSED`）。
5. 冒烟**串行**跑：先六条 web（临时 home），再六条桌面（live 版 + CDP 9222），不要并发。桌面回归之间**先切回会话视图**；agent 自己跑 advisor / next-step 回归前，先切到**空闲会话**。
6. 新建 `docs/runtime/<新版本>.md`，更新 AGENTS.md、plugin-conventions、两份根 README 的徽章、各插件兼容表与测试手册（`pnpm check:docs` 会拦）；重跑 `pnpm tokens:host` 并确认快照 `_meta.dshVersion` 跟着变（`--check` 不看 `_meta`，别被「新增 0、移除 0」骗过去）。
7. 桌面脚本的收尾行格式不能改；新增脚本时照抄 `N PASS / M SKIP / K FAIL`，否则门禁的假绿检测对该脚本失效。
