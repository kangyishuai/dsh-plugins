## 0. 一句话结论

0.2.2-rc.1 → 0.2.2-rc.2 对插件**没有发现破坏性变化**：探针 67/67 PASS、`pnpm verify` 全绿、会话日志仍是 v4、版本闸门语义未变；web 与桌面端只读冒烟在 rc.2 上重跑通过（§6）。**四个插件的代码不需要改。**

仓库里改了三处，都是测试/检查工具：探针 3 条正则适配 rc.2 压缩后的 client 半（§2）、advisor 桌面冒烟改成取最后一个设置卡节点（§6）、session-delete 风险说明补工作树清理（§5.1）。两处宿主行为变化要知道：归档会清理干净的工作树（§5.1）、macOS 浮层窗口区域（§5.2）。

macOS 浮层窗口区域：物理拖动复核发现回溯抽屉确实会把窗口拖走，已加 `data-window-drag-exclude` 修好并复验（§5.2）；这一条也写成了 changeset（session-rewind / session-delete patch）。session-delete 冒烟那条失败断言已定位并修好（§7）。

实测基线：`dsh --version`、`Info.plist`、`app.asar` 内 `/package.json` 与 `/dsh/package.json` 都是 `0.2.2-rc.2`。

## 5. 两处需要留意的宿主行为变化

### 5.1 归档会清理「干净」的工作树（影响 session-delete）

升级指南 _Worktree cleanup on archive_ 的原文要点：

- 工作树服务现在把它创建的每个检出目录记录成 `plugin:worktree/created` 会话事件；创建它的会话被归档时，若没有未归档会话引用该目录、创建者策略不是只读、且 Git 没发现跟踪文件改动 / 未跟踪文件 / 已初始化子模块 / 锁 / 分离 HEAD，就用不带 `--force` 的 `git worktree remove` 删掉它。
- 被忽略的文件（如 `node_modules`）和 skip-worktree / assume-unchanged 的改动不会保留目录，Git 会丢弃。
- 分支与提交保留；服务有 `retainOnArchive`（默认关闭），开启后保留所有检出目录。

**对本仓库的影响**：session-delete 的「移入回收站」正是 `workspaceRegistry.archiveSession()`，所以从 rc.2 起，删除一个会话可能**连带删除它的干净工作树**。插件没有接入宿主的工作树服务，确认框无法区分「有没有工作树」，因此不改确认框结构；风险写进 `packages/session-delete/README*.md` 的副作用一节。要保住检出目录：归档前 `git worktree lock`，或在 Forge 套件的 worktree 行上开 `retainOnArchive`。

### 5.2 macOS 浮层窗口区域（window drag）

rc.2 的随包 CSS（`dsh-web-frontend/dist/assets/index-*.css`）把窗口拖动改成了显式声明：

```css
html[data-platform="darwin"] * { -webkit-app-region: initial }
html[data-platform="darwin"] [data-window-drag] { -webkit-app-region: drag }
html[data-platform="darwin"] body > :not(#root) { -webkit-app-region: no-drag }
html[data-platform="darwin"] [data-window-drag-exclude] { -webkit-app-region: no-drag }
html[data-platform="darwin"] :where([data-window-drag], [data-window-drag-controls]) :is(button, a, input, …) { -webkit-app-region: no-drag }
```

即：默认是 `initial`（计算值 `none`），只有 `[data-window-drag]` 子树是拖动区；此前「任意位置的控件都自动 no-drag」的规则没有了。注意 **`none` 不等于排除**：原生拖动命中区只收集 `drag` 矩形，`none` 元素不会在它下面「挖洞」，所以压住页头的普通浮层仍会命中底下的 `[data-window-drag]`，必须显式写 `data-window-drag-exclude`（计算值 `no-drag`）。

**结论（2026-11-12 物理拖动复核后更正）：需要迁移，已修。**

- 第一次只用 CDP 看了计算样式：回溯抽屉/遮罩都是 `none`，误以为等价 no-drag，写了「不需要迁移」——**这个判断是错的**。
- 之后用 CGEvent 合成真实鼠标事件重做物理拖动（校准：在宿主页头 `[data-window-drag]` 上拖 40px，窗口从 `(0,30)` 移到 `(40,30)`，说明方法有效）。同样在回溯抽屉头部（压在页头上）拖 40px，窗口**又被拖走 40px**：抽屉没有排除底下的拖动区。
- 修法：给 `.dsh-srw-drawer`、`.dsh-srw-drawer-mask`、`.dsh-srw-mask` 加 `data-window-drag-exclude`；session-delete 的自绘确认框 fallback 遮罩也显式声明（它平时走宿主 `Modal`，portal 根已有 `no-drag`，所以回收站面板的物理拖动本来就是安全的）。
- 复验：重新打包安装、刷新页面后，在同一个点拖 40px，窗口保持在 `(0,30)`；抽屉保持打开，`smoke:session-rewind-desktop` 23/23、`smoke:session-delete-desktop` 14/14 通过。

手感仍需人手一次（浮层开在页头上方，确认按钮可点、关闭后页头空白可拖）；但「拖动会不会拖走窗口」这一条已经用真实鼠标事件验证过。

## 6.1 主题 token 清单

宿主在 `body` / `body[data-ds-dark-theme]` 里定义主题 token。rc.2 的 design-platform + base 样式表里共 **456 个** `--dsw-*` / `--ds-*` 定义，已抽成快照提交在 [`scripts/lib/host-theme-tokens.json`](../../scripts/lib/host-theme-tokens.json)，由 `pnpm check` 用来校验插件 CSS。

**为什么要固化这份清单。** 插件只能用宿主真实存在的 token。写错名字时 CSS **不会报错**，`var()` 会静默使用第二个参数（我们惯用的硬编码兜底色），于是那段样式永远不跟随深浅色主题。这个坑在本仓库真实踩过三次：

| 现象                                             | 根因                                                                                                          |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| 确认按钮在深色主题下白底白字（0.6.1 → 0.6.2）    | `--dsw-alias-brand-primary` 是**反色表面色**（浅色 `#0f1115`、深色 `#f9fafb`），配写死的 `#fff` 前景 → 1.05:1 |
| 警告文案在两个主题下同一个暗金（0.5.0 → 0.5.1）  | 用了不存在的 `--dsw-alias-state-warning-primary`（真名 `state-warn-*`）→ 永远落到 `#b7791f`                   |
| 回收站计数徽章深色下只有 3.29:1（0.4.8 → 0.4.9） | `state-error` 底色是浅红 `#f25a5a`，配写死白前景                                                              |

**权威 token 名。** 语义命名规律：`--dsw-alias-<类别>-<档位>`。类别有 `bg`(`base/layer-1..3/overlay/mask-N/module-platform`)、`border`(`l1..l4`)、`label`(`primary/secondary/tertiary/caption/primary-foreground/primary-inverted/on-color`)、`brand`(`primary`)、`state`(`error/success/warn/business` × `primary/secondary/label/tertiary`)、`button`(`primary-fill/primary-hover/primary-dimmed`)、`interactive`(`bg-hover/bg-hover-danger`)、`link`、`toast`(`bg/label`)。注意是 `state-warn-*`，**没有** `state-warning-*`。

关键配对（前景必须跟着底色翻转，不能写死）：

| 底色                                                            | 配对的文字色                           |
| --------------------------------------------------------------- | -------------------------------------- |
| `--dsw-alias-brand-primary` / `--dsw-alias-button-primary-fill` | `--dsw-alias-label-primary-foreground` |
| `--dsw-alias-state-error-primary`                               | `--dsw-alias-label-primary-foreground` |
| `--dsw-alias-toast-bg`（两个主题都是深色）                      | `--dsw-alias-toast-label`              |

**DSH 升级后怎么更新快照**（CI 里没有 DSH，所以只能本地生成再提交）：

```bash
pnpm tokens:host          # 从本机 DeepSeek Harness 的 app.asar 抽 token，重写快照
pnpm tokens:host:check    # 只比对：宿主有新增/移除时报出来，不写文件
```

脚本直接按字节扫 asar 里的 `--dsw-*:` 定义（不解析归档结构，对新版本布局不敏感）；抽到的数量少于 100 就报错而不是静默写空快照。**新增 token 不需要立刻用**，但移除的 token 若被插件引用，`pnpm check` 会直接报 error。

| 宿主 `Modal` 打开时会把焦点交给 `[data-modal-autofocus]`，没有则交给第一个可聚焦元素                                                 | `dsh-web-frontend` bundle 里 Modal 的挂载逻辑                                                               | 「确认按钮默认选中」用它，比自己 `autoFocus` 稳（宿主负责焦点陷阱与恢复）               |
| 宿主 `Checkbox` 支持 `modalAutofocus` 属性；`Switch` 渲染出的不一定是 `input`（可能是 `role="switch"` 的按钮）                       | 同上 bundle                                                                                                 | 断言「开关已打开」时要同时接受 `aria-checked` 与 `input.checked`                        |
| 侧栏底部的设置入口在装了账号插件后会被 `settings.launcher` 的账号版本替换（`aria-label` 不再是「设置」）                             | `dsh-client-ui-settings-account/src/client/index.ts` 注册 `settings.launcher`                               | 自动化里找设置按钮要留兜底（设置 / 账号菜单 / `aria-haspopup="dialog"` / `⌘⌥,`）        |
| `sidebar.footer.action` 的宿主任主条目是 `cordis-panel`，`order` 只在本插件自己的条目间排序                                          | `cordis_inspect_query`（client Slots）                                                                      | 页脚入口的 `order` 不必和宿主比大小                                                     |

> 结论：**没有构建步骤的 client 插件同样能做「加进官方设置页 / 官方菜单 / 官方快捷键」**，
> 前提是走宿主已有的 slot 与 service，而不是自绘一套。session-delete 0.5.0 的设置页就是这么加的。

## 7. session-delete 冒烟那一项：已定位并修复

第一次跑是 **23/24**：断言「确认删除后，侧栏里 `[data-row-key^='session:']` 的行数应减 1」实测 `6 -> 6`，其余功能断言全过。

把行 ID 和元素信息打出来后定位到根因：**侧栏第一行是「新会话」**——还没落盘的临时会话，它的 `data-row-key` 同样是 `session:<id>`，但不是一条可删除的真实会话。冒烟把这一行当成「被删的那一行」，于是：

- 删除后它当然还在（它是常驻的新会话入口），行数不变；
- 真正被删的是另一条真实会话，所以 toast、回收站、刷新不复活、恢复、彻底删除这些断言都正常。

还有两个因素让原断言更脆：侧栏只渲染固定条数，删掉一行可能从折叠组补一行进来（总数不变）；行未激活时「…」菜单按钮不在 DOM 里，冒烟可能点到别的行的菜单按钮。

修法（只改冒烟脚本，不改插件代码）：

1. `rows()` 与 `openConfirm()` 过滤掉文本为「新会话 / New chat / 未命名」的行；
2. 打开菜单前先点一下目标行把它激活，再 hover，确保拿到这一行自己的「…」按钮；
3. 断言改成**按 ID**：被删的 `data-row-key` 不在删除后的列表里，恢复后又出现；行数只放在 detail 里。

修完在 rc.2 上复跑 **24/24 PASS**（2026-11-12）。冒烟用的是临时 `DSH_HOME`：它把真实的 `~/.dsh/sessions` 与 `storages` 复制进去再操作，不写真实数据。

## 8. 下次升级要做什么

1. 升级前先跑一次 `pnpm probe:runtime` 留基线，升级后立刻再跑；先分清「能力没了」和「源码形态变了导致匹配不到」——rc.2 这次就是后者。
2. 新建 `docs/runtime/<新版本>.md`，更新 AGENTS.md、`plugin-conventions.md`、两份根 README 与各插件徽章/兼容表（`pnpm check:docs` 会拦）。
3. 重点看三件事：`SESSION_FORMAT_VERSION`、`sessionPersistence` 是否终于有删除 API、`satisfies` 的 options 有没有变；外加 client 半有没有再换构建形态。
4. 临时 `DSH_HOME` 的 web 冒烟（`smoke:session-rewind` / `smoke:advisor` / `smoke:session-delete`）可以直接跑；桌面冒烟需要重启并开 CDP，安排在升级后第一次重启时做。
5. 逐条过新版本的 `docs/upgrade-guide/<上一版>/`，把「影响本仓库」的条目写进新文档。
