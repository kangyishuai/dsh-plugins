# DSH 0.2.2-rc.2 运行时勘察记录

> **适用版本：DSH 桌面版 0.2.2-rc.2。** 来源：`app.asar` 内随包源码、随包的 `docs/upgrade-guide/v0.2.2-rc.1`（20 条升级指南）、本机探针与端到端冒烟。
>
> 上一版见 [0.2.2-rc.1.md](0.2.2-rc.1.md)；稳定的工程约定写在 [../plugin-conventions.md](../plugin-conventions.md)。

## 0. 一句话结论

0.2.2-rc.1 → 0.2.2-rc.2 对插件**没有破坏性变化**：探针 67/67 PASS、`pnpm verify` 全绿、会话日志仍是 v4、版本闸门语义未变，**四个插件的代码不需要改**。

唯一需要改仓库代码的是**探针本身**：rc.2 起 client 半随包 JS 被压缩，3 条写死双引号的匹配误报 FAIL（见 §2）。另外有两处宿主行为变化要知道：归档会清理干净的工作树（§5.1，影响 session-delete 的风险说明）、macOS 浮层窗口区域（§5.2，核对后不需要迁移）。

实测基线：`dsh --version`、`Info.plist`、`app.asar` 内 `/package.json` 与 `/dsh/package.json` 都是 `0.2.2-rc.2`。

## 2. 探针：67/67，以及 3 条误报的根因

`pnpm probe:runtime` 在 rc.2 上：**67 项全 PASS**（宿主包 / API / 私有 seam / slot 四类）。第一次跑的结果是 64 PASS + 3 FAIL，3 条 FAIL 全部是**压缩产物导致的误报**，不是宿主删了能力：

| 检查                                  | 探针原来的正则                                         | rc.2 实际源码（原文）                                                |
| ------------------------------------- | ------------------------------------------------------ | -------------------------------------------------------------------- |
| client slots 服务（`SlotRegistry`）   | `/super\(ctx, "slots"\)/`                              | ``super(ctx,`slots`)``                                               |
| `conversation.chat.node` 注册 user 行 | `/conversation\.chat\.node[\s\S]{0,200}key:\s*"user"/` | ``ctx.slots.register({name:`conversation.chat.node`,key:`user`,…})`` |
| 输入框 `submit(mode = "queue")`       | `/submit\(mode = "queue", source\)/`                   | ``submit(mode=`queue`,source,allowEmpty=false)``                     |

三条能力都还在，插件在 rc.2 上也确实走通了对应链路（§6 的 rewind 49/49 覆盖了 ↶ 按钮与输入框回填）。修法：`scripts/probe-runtime.mjs` 里这三条正则改成 [`"'] 字符类并允许 `\s*`，rc.1 及更早的未压缩源码仍然匹配。

**连带影响**：[0.2.2-rc.1.md](0.2.2-rc.1.md) 里引用的 client 行号（例如 `dsh-client-ui-commands/lib/client.js:1894-1925`）在 rc.2 上已经失效——同一个文件现在只有 5 行。以后引用 client 源码时尽量引「符号 + 附近代码」，不要引行号。

压缩范围：`dsh-client-ui-*` 的 `lib/client.js`，实测 3–27 行（如 chat 20 行 / 478 KB、conversation 27 行 / 653 KB）。宿主侧的 `lib/index.js`（`dsh-app-boot` 5336 行、`dsh-session` 2143 行）**没有压缩**。

## 5. 两处需要留意的宿主行为变化

### 5.1 归档会清理「干净」的工作树（影响 session-delete）

升级指南 _Worktree cleanup on archive_ 的原文要点：

- 工作树服务现在把它创建的每个检出目录记录成 `plugin:worktree/created` 会话事件；创建它的会话被归档时，若没有未归档会话引用该目录、创建者策略不是只读、且 Git 没发现跟踪文件改动 / 未跟踪文件 / 已初始化子模块 / 锁 / 分离 HEAD，就用不带 `--force` 的 `git worktree remove` 删掉它。
- 被忽略的文件（如 `node_modules`）和 skip-worktree / assume-unchanged 的改动不会保留目录，Git 会丢弃。
- 分支与提交保留；服务有 `retainOnArchive`（默认关闭），开启后保留所有检出目录。

**对本仓库的影响**：session-delete 的「移入回收站」正是 `workspaceRegistry.archiveSession()`，所以从 rc.2 起，删除一个会话可能**连带删除它的干净工作树**。插件没有接入宿主的工作树服务，确认框无法区分「有没有工作树」，因此不改确认框结构；风险写进 `packages/session-delete/README*.md` 的副作用一节。要保住检出目录：归档前 `git worktree lock`，或在 Forge 套件的 worktree 行上开 `retainOnArchive`。

### 5.2 macOS 浮层窗口区域（window drag）

rc.2 的随包 CSS（`dsh-web-frontend/dist/assets/index-*.css`）把窗口拖动改成了显式声明：

```css
html[data-platform="darwin"] * { -webkit-app-region: initial }
html[data-platform="darwin"] [data-window-drag] { -webkit-app-region: drag }
html[data-platform="darwin"] body > :not(#root) { -webkit-app-region: no-drag }
html[data-platform="darwin"] [data-window-drag-exclude] { -webkit-app-region: no-drag }
html[data-platform="darwin"] :where([data-window-drag], [data-window-drag-controls]) :is(button, a, input, …) { -webkit-app-region: no-drag }
```

即：默认是 `initial`（no-drag），只有 `[data-window-drag]` 子树是拖动区；此前「任意位置的控件都自动 no-drag」的规则没有了。指南要求覆盖页头的自定义浮层在可见视口上声明 `data-window-drag-exclude`。

**本仓库核对结论：不需要迁移。** 四个插件的浮层都挂在 `shell.overlay` / `conversation.input.overlay` 等槽位上，根节点是 `position: fixed` 的普通 `div`，**不在任何 `[data-window-drag]` 行内**；session-delete 的对话框优先用宿主共享 `Modal`，自绘 fallback 同样不在拖动区内。因此按钮不会变成拖动把手。**注意：本会话无法重启桌面版开 CDP，未做真机拖动实测**；下次能重启时按指南第 4 步在 macOS 上点一遍（把浮层开在页头上方，确认控件可用、关闭后页头空白仍可拖）。

## 7. session-delete 冒烟的那 1 项

断言是「确认删除后，侧栏里 `[data-row-key^='session:']` 的行数应减 1」。在 rc.2 上实测 `6 -> 6`，但同一轮里后面的断言全部通过：出现「已移入回收站」toast、刷新后该会话不复活、回收站列出条目、恢复与彻底删除都正常；截图（`04-after-delete.png`）里被删的那一行确实从侧栏消失了（`展开其余 N 个会话` 的 N 也随之变化）。

把行 ID 打出来后更清楚：`afterRows` 里**仍含**被删的 `data-row-key`，同时另一条会话行从 DOM 消失（两次重跑丢的是不同的行），还有一条新 ID 补进来。这说明 rc.2 侧栏在删除/重建会话列表时复用了行节点、或按固定条数重新铺了可见行，`data-row-key` 与「视觉上的那一行」不再一一对应；行数断言不可靠，不是删除链路的问题。

结论：**删除链路本身正常**（toast、回收站、刷新不复活、恢复、彻底删除、审计、回执全部通过），失败的是冒烟脚本里的 DOM 行数断言。本次没有改它——属于冒烟脚本的后续修复（建议改成「按标题/可见文本判断被删会话消失」，或等宿主提供稳定的行标识），修好后这一项应该回到 24/24。冒烟用的是临时 `DSH_HOME`：它把真实的 `~/.dsh/sessions` 与 `storages` 复制进去再操作，不写真实数据。

## 8. 下次升级要做什么

1. 升级前先跑一次 `pnpm probe:runtime` 留基线，升级后立刻再跑；先分清「能力没了」和「源码形态变了导致匹配不到」——rc.2 这次就是后者。
2. 新建 `docs/runtime/<新版本>.md`，更新 AGENTS.md、`plugin-conventions.md`、两份根 README 与各插件徽章/兼容表（`pnpm check:docs` 会拦）。
3. 重点看三件事：`SESSION_FORMAT_VERSION`、`sessionPersistence` 是否终于有删除 API、`satisfies` 的 options 有没有变；外加 client 半有没有再换构建形态。
4. 临时 `DSH_HOME` 的 web 冒烟（`smoke:session-rewind` / `smoke:advisor` / `smoke:session-delete`）可以直接跑；桌面冒烟需要重启并开 CDP，安排在升级后第一次重启时做。
5. 逐条过新版本的 `docs/upgrade-guide/<上一版>/`，把「影响本仓库」的条目写进新文档。
