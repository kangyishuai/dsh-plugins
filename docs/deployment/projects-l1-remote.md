# projects：L1 远程访问（单机）

本文只讲**怎么从另一台设备连到同一台机器上的 DSH**，以及 `projects` 在这种用法下的边界。
它不引入任何服务端组件——这是 [ADR 0020](../adr/0020-projects-no-cloud-execution.md) 的边界。

## 1. 先说清楚 L1 是什么、不是什么

|          | 说明                                                                                    |
| -------- | --------------------------------------------------------------------------------------- |
| **是**   | 你人在另一台设备（笔记本、平板、手机浏览器），连回**自己那台常驻机器**上的 DSH Web UI   |
| **不是** | 云端执行：线程不在容器里跑，关掉那台机器就停                                            |
| **不是** | 多设备同步：没有账号体系，没有远端存储，没有单写者租约                                  |
| **不是** | 多人协作：项目共享已推迟（[ADR 0018](../adr/0018-projects-defer-liveshare-sharing.md)） |

对 `projects` 的具体含义：

- 项目元数据、`instructions.md`、`memory/`、线程 worktree **全部在那台机器的磁盘上**；
- 协调器与线程都在那台机器上跑，远程浏览器只是**看与操作**；
- 换设备不会带来"接着上次的上下文"——上下文属于那台机器上的项目目录。

## 2. 安全地暴露 Web UI

DSH 的 Web 服务**拒绝通配地址**（`--host` 只接受某个具体本机接口），所以"监听 0.0.0.0"这条路本来就不通。
推荐两种做法：

### 2.1 回环 + 隧道（最省心）

```bash
# 机器 A：只绑回环
dsh web --host 127.0.0.1 --port 8080 --no-open

# 设备 B：用 SSH 隧道（或 Tailscale / WireGuard 等）
ssh -N -L 8080:127.0.0.1:8080 me@machine-a
# 然后浏览器打开 http://127.0.0.1:8080
```

### 2.2 绑具体接口 + HTTPS

```bash
dsh web --host 10.0.0.7 --port 8443 \
  --tls-cert ./server-chain.pem --tls-key ./server-key.pem
```

跨不可信网络时**必须**用 HTTPS：`dsh-auth-*` 是普通 cookie，明文 HTTP 下会被同网段看到。

### 2.3 放在反向代理后面

代理会改写 authority，需要显式放行，否则 `/api` 的浏览器信任围栏会拒绝：

```bash
dsh web --host 127.0.0.1 --port 8080 \
  --public-url https://app.example/ui/ --trusted-host app.example
```

`--public-url` 只影响**展示与运行时上下文里的地址**，不授予任何信任；信任由 `--trusted-host` 决定。

## 3. 登录态怎么来

启动时 DSH 会打印一个带 token 的入口：

```
http://127.0.0.1:8080/?token=<一次性 token>
```

第一次访问会 303 到 `/`，并下发 `dsh-auth-*` cookie；之后靠 cookie 认证。

两个容易踩的点：

1. **cookie 按主机作用域、忽略端口**。同一台机器上反复启动不同实例，会堆出一批指向已死实例的
   `dsh-auth-*`，表现为 401 或导航失败。清掉**仅** `127.0.0.1` 上 `dsh-auth-` 前缀的 cookie 即可
   （不要用"清空所有 cookie"，那会连带清掉你其它站点的登录态）。
2. **token 是一次性的**。不要把带 token 的 URL 贴进聊天工具或工单；需要重新进入时重启服务拿新的。

## 4. 远程使用时的 `projects` 冒烟清单

在**远程浏览器**里逐条确认（不需要模型凭据，不花 token）：

- [ ] 侧栏出现「项目」入口，点击后面板渲染（不是空白、不是崩溃页）
- [ ] 面板顶部摘要显示项目数与状态（`data-projects-status` 形如 `ready|3|ok|`）
- [ ] 新建一个项目后，列表出现该行；刷新页面仍在（说明写到了那台机器的磁盘）
- [ ] 详情页能打开，页签（线程 / 记忆 / 审计）都能切换且不报错
- [ ] 「归档」按钮可用；归档后宿主侧 `projects.json` 里 `state` 变成 `archived`
- [ ] 设置页出现「项目」分节（若该 profile 禁用了设置页，此项允许跳过）
- [ ] 断网再恢复：面板能重新加载，不出现永久 loading

自动化版本见 [docs/testing/projects.md](../testing/projects.md)（web 冒烟 51 项）与
`pnpm smoke:projects-desktop`（桌面只读回归 11 项）。

## 5. 已知限制

- **没有多设备接续**：换设备不会带上下文，因为上下文属于机器上的项目目录。
- **没有共享**：把项目分享给另一个人需要 LiveShare，而它在当前 DSH 版本里未启用（ADR 0018）。
- **危险动作的授权仍然只来自本机**：远程浏览器里点"批准"算 `per-incident` 授权；
  模型输出、外部内容永远不构成授权（[ADR 0019](../adr/0019-projects-authorization-model.md)）。
- **关掉那台机器就停**：没有云端兜底。
